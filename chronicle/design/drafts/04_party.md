# 04 主人公の作成と仲間 20 人（DESIGN.md 用ドラフト）

この章は、主人公の作り方（性別・タイプ・得意分野・名前）と、最初から選べる仲間 20 人のすべての数値・文・見た目、
酒場での入れ替えの規則を決める。**実装担当は newgame（A6）**。データのファイルは `src/data/herotypes.js` と `src/data/companions.js`。
絵は art-chars（A13）が `src/art/chars_party.js`（新しいファイル）に作る。

- 数値の式（最大 HP の曲線・得手不得手の倍率・熟練度・閃き）は **02 成長章（rules）が正**。この章はその式に入れる**値**を決める。
- エンジン章（01）の API とスキーマの形は変えない。足した項目は §0 と §8 に書いた。
- 表の数値・文の幅・予算は、すべて node のスクリプトで検算した（§4.4）。表と §3.9 のデータは同じ元データから作ったので、食い違いはない。

## 2. 主人公の作成

### 2.1 流れ（`R.CharCreate.run()`、エンジン章 §5.12）
プロローグのイベントの中で `ev.createHero()` が呼ぶ。語り部の師匠に「見習いよ、おまえはどんな者だったかな」と問われる形（台本は物語章）。
1. **性別**: 男 / 女。2 つの絵（`party:hero_m_warrior` と `party:hero_f_warrior`）を並べて選ぶ。見出し「性別を選んでください」
2. **タイプ**: 5 つのリスト。カーソルの位置のタイプについて、説明（`desc` 2 行）・能力値 6 つ（数字と棒）・成長の型（HP/MP/WP の文字）・その性別の絵を右に出す。見出し「タイプを選んでください」
3. **得意分野**:
   - `favorKind:'weapon'` → 武器系統のリスト（`favorOptions.weapon`）。見出し「得意な武器を選んでください」
   - `favorKind:'element'` → 属性のリスト（6 つ）。見出し「得意な属性を選んでください」
   - `favorKind:'any'` → まず「武器／属性」を選び、次にそのリスト（魔剣士は武器 5・属性 6、旅人は武器 11・属性 6）
   - 各行にアイコン（`icon:<wtype>` か `icon:el_<element>`）と名前、下の窓に 1 行の説明（§2.5）。術師なら「組の属性：風も○になる」と添える。
4. **名前**: `R.NameEntry.run({initial, max:5, spriteKey})`（§2.6）
5. **確認**: 絵・名前・タイプ・得意分野を並べて「この姿と名前で始めますか？」はい／いいえ。いいえなら 1 に戻る。
- どの段でも B で 1 つ前の段に戻る。性別の段で B なら何もしない（`cancel:false` のとき）。
- 返り値 heroSpec = `{name, gender, type, favor:{kind, id}}` → `R.State.newGame(heroSpec)` のあとの `R.Rules.newChar({id:'hero', heroSpec})` が §2.7 の手順で CharState を作る。

### 2.4 得意分野の効果（規則）
選んだ得意分野 `favor = {kind:'weapon'|'element', id}` は、次をすべて与える。
| 効果 | 武器を選んだとき | 属性を選んだとき |
|---|---|---|
| 得手不得手 | その系統が **S** | その属性が **S**。術師だけ、組の属性も **A**（火↔風、水↔光、土↔闇） |
| 熟練度 | その系統 15 ポイント（段階 2） | その属性 15 ポイント（段階 2） |
| 初期の武器（武器 1） | その系統の初期武器（§1.4） | タイプの既定の武器: 術師 `w_staff_novice`、魔剣士 `w_sword_iron`、旅人 `w_dagger_iron` |
| 初期の技・術 | その系統の入門技（§1.2） | その属性の 1 段の術（§1.3） |
| 魔剣士だけ、さらに | 術 `s_fire_1` | 技 `t_sword_stepcut` |
- ほかの得手不得手の A は熟練度 5 ポイント（段階 1）、S は 15 から始まる（仲間と同じ規則。0.6）。
- 検算（武器の合計 / 属性の合計。予算の範囲は 15〜19 / 8〜12）:

| タイプ | 武器を選んだとき | 属性を選んだとき | 合計 |
|---|---|---|---|
| 戦士 | 19 / 8（どの系統でも） | — | 27 |
| 狩人 | 18 / 9 | — | 27 |
| 術師 | — | 16 / 11（S＋組の A） | 27 |
| 魔剣士 | 17〜18 / 9 | 15 / 11〜12 | 26〜27 |
| 旅人 | 17〜18 / 9 | 15 / 11〜12 | 26〜27 |
- 魔剣士・旅人は 1 点少ない組み合わせがある代わりに、選べる幅が広い（旅人は能力値の偏りも無い）。

### 2.7 CharState の作り方（`R.Rules.newChar`。規則）
```
newChar({id:'hero', heroSpec:{name, gender, type, favor}}):
  T = DB.heroTypes[type]
  apt = clone(T.apt);  K = favor.kind === 'weapon' ? 'w' : 'e'
  apt[K][favor.id] = 'S'
  if (T.pairElement && favor.kind === 'element') apt.e[DB.starterKit.pair[favor.id]] = 'A'
  wprof/eprof = 各系統・属性について {S:15, A:5}[apt の文字] || 0         // DB.starterKit.prof
  equip.weapon1 = favor.kind === 'weapon' ? DB.starterKit.weapon[favor.id] : T.defaultWeapon
  equip.body/head/shield = T.startEquip の body/head/shield
  もし weapon1 が両手持ちなら shield = null
  techs  = (favor.kind === 'weapon' ? [DB.starterKit.tech[favor.id]] : []) ＋ T.onFavor[favor.kind].techs
  spells = (favor.kind === 'element' ? [DB.starterKit.spell[favor.id]] : []) ＋ T.onFavor[favor.kind].spells
  row = T.row === 'auto' ? (reach(weapon1) === 'any' || favor.kind === 'element' ? 'middle' : 'front') : T.row
  level 1、hp/mp/wp は最大値、name = heroSpec.name、gender、heroType = type、favor を保存
newChar({id:companionId, level?}):
  D = DB.companions[id];  apt = D.apt;  wprof/eprof は上と同じ規則（S 15・A 5）
  equip = D.startEquip、techs = D.startTechs、spells = D.startSpells、row = D.row、name = D.name、gender = D.gender
```

### 2.9 しゃべらない主人公の約束（全章）
- 主人公の台詞は書かない。選択肢は「はい／いいえ」か、行動の選択（「行く／やめる」など）だけ。

- 仲間がしゃべるのは、加入・控えへ・出撃へ の 3 つの台詞と後日談だけ（§3.6）。

### 3.6 台詞と文（全員。1 行は全角 20 字まで、`{hero}` は 5 字として数えた）
- `profile`（3 行）: 酒場の画面に出す。語り部の手帳の書き方（〜らしい、〜という）で、本人の台詞ではない。
- `joinLine`（2 行まで）: 初めて仲間になったとき。「{name}が仲間に加わった！」（ジングル `recruit`）の次に出す。
- `leaveLine`（1 行）: 出撃から控えに回ったとき。`rejoinLine`（1 行）: 控えから出撃に戻ったとき（2 回目以降の出撃。最初の加入は joinLine）。
- `epilogue`（2 行）: エンディングで、出撃中の仲間それぞれについて出す（エンジン章 §5.12 `R.Ending`）。控えの人の後日談は出さない。
- 話者名・かぎかっこは付けない（クレストの表記ガイドと同じ）。
- この章の文に出る `{name}` は、酒場・加入の処理がその人の `c.name` に置き換える（`R.Text.fmt` に `{name}` を渡す）。データの文（profile など）には `{name}` を書かない。

## 4. バランスの考え方（どの 3 人＋主人公でもクリアできる、最強の 3 人が決まらない）

### 4.1 原則
1. **予算をそろえる**: 能力値 200・得手不得手 27・成長 6 を全員に同じだけ配る（0.4）。違うのは「どこに配ったか」だけ。
2. **専門家と万能型**: 専門家は S を 1 つ持ち、代わりに D を 2〜4 つ持つ（例: バジル 棍棒 S・D 4 つ）。万能型は S を持たず B が多い（例: バルトロ・ヴィオラ・ベラドナ・フェルノ）。
   専門家は得意な道の技を 2 倍の速さで閃くが、ほかは遅い。万能型はどの道もそこそこ閃く。閃いた技の強さは同じ（技の威力に得手不得手は効かない）。
3. **能力値で誰も誰かを上回らない**: どの 2 人を比べても、**6 つの能力値すべてで上回る（か等しい）人はいない**（検算済み）。最高値は 58（ハーゲンの腕力、ドッカの体力、ティッタの素早さ、シルヴァンの器用さ、テオの知力）で、成長章 §2.1 の上限 60 に届かない。主人公の最高値も 58。
4. **役割は 3 人以上で重なる**: どの武器系統も S/A が 3〜4 人、どの属性も 4〜5 人（§3.3）。前列 10・中列 10。回復（光か水が A 以上）は 9 人（成長章 §2.1 の「8 人以上」を満たす）。
5. **誰でも回復を覚えられる**: 全員が光か水のどちらかで C 以上（成長章 §2.1）。回復役のいない 3 人組（1140 組のうち 165 組）でも、主人公が光・水を選ぶか、魔石（成長章 §9.6、覚えていない属性の最初の閃きは 10 倍）で光の術を始められる。
   さらに、戦闘の後は HP 全快・蘇生の道具は T0 から安く買える（成長章 §12）ので、回復役なしでも進める。
6. **戦闘の強さに効く個性を作らない**: 個性は、お金・ドロップ・出会い・逃げやすさ・状態異常の守り・フィールドの便利さだけ（§3.4）。
   「全体に効く」個性はそれぞれ 1 人しか持たない（`goldPct dropPct rarePct superPct rareEncPct goldenPct preemptPct escapePct noFloorDamage`）ので、レア狙いの組は作れても、戦闘が強くなる組にはならない。
7. **最初の一手はだれでも持つ**: どの人も、おすすめの隊列から初めての戦闘で使える攻撃（届く武器の技か、攻撃の術）を持っている。中列の術師は鞭を持つ（0.9）。
8. **追いつける**: 入れ替えた仲間は、途中加入の熟練度（成長章 §9.1）・閃きの追いつき FK（§9.4）・格上からの経験値の増え（§2.3）で、2〜3 地方のうちに主力と並ぶ。

## 5. 酒場と入れ替えの規則（規則。担当 newgame・rules・menu）

### 5.1 どこで何ができるか
| 場所 | 加入（未加入の候補を仲間にする） | 入れ替え・並び・隊列 | 控えの装備をあずかる |
|---|---|---|---|
| **酒場のマスター**に話す（`R.Tavern.open({recruit:true})`） | ○ | ○ | ○ |
| 町・村・城の中で、フィールドのメニュー「仲間」（`R.Tavern.open({recruit:false})`、`R.Party.canSwapHere()` のときだけメニューに出す） | × | ○ | ○ |
| ダンジョン・ワールドマップ・戦闘の中 | × | ×（並びと隊列だけは、いつものメニューの「並び替え」でできる） | × |
- **酒場は町・城下町ごとに 1 つ**置く（村には置かなくてよい）。マスターは `npc:bartender`。どの酒場でも同じ名簿（未加入の全員）を扱う。
- 最初の町の酒場で、物語のイベント（`ev.chooseCompanions()`）が `R.Tavern.chooseStart({count:3})` を開き、最初の 3 人を選ぶ（§6.2）。それより前には酒場は開かない（物語章）。

### 5.2 加入
- いつでも、何人でも、お金はかからない。一度加入した人は抜けない（控えに回るだけ。解雇はない）。
- `R.Party.recruit(id, {toParty})`: 出撃が 4 人未満なら出撃へ、満員なら控えへ。加入のレベル `joinLevel()` = max(1, floor(主人公のレベル × 0.9))（エンジン章 §5.4）。HP/MP/WP は最大値。
- 熟練度: 最初の 3 人は §0.6 の開始値。**4 人目以降**（途中加入）は成長章 §9.1 の追いつきの式。技・術は `startTechs`/`startSpells` だけ。装備は §3.5 の初期装備（ティア 0）。
- 演出: ジングル `recruit` → 「{name}が仲間に加わった！」 → joinLine。控えに入ったときは続けて「{name}は控えで待っている。」

### 5.3 入れ替え
- 出撃は主人公を含む 1〜4 人。**主人公は外せない**。4 人に満たないまま旅をしてもよい。
- 出撃の人と控えの人を選んで入れ替える（`R.Party.swap`）。出撃の人だけを選んで「はずす」、控えの人だけを選んで「加える」（出撃が 4 人未満のとき）もできる。
- 出撃に入った人は**全快**（HP/MP/WP・状態。エンジン章 §0.10）。控えに回る人の HP などは気にしない（次に出撃するとき全快する）。
- 台詞: 控えに回る人の leaveLine → 出撃に入る人の rejoinLine の順に出す（1 人につき 1 行、A で送る）。効果音 `swap`。
- 入れ替えた人は、出撃の最後尾に入り、隊列はデータの `row`（主人公はそのまま）。並びと隊列は同じ画面で直せる。

### 5.4 控え（`R.Game.reserve`）
| 項目 | 規則 |
|---|---|
| 経験値 | 出撃中で生きている人が受ける量の **60%**（`R.Party.award`、share 0.6。レベル差の減り方 f(d) は控えの人のレベルで計算する。成長章 §2.3） |
| 熟練度 | **増えない** |
| 閃き | **無い**（戦闘に出ないので判定が起きない） |
| 装備 | 付けたまま。所持品として数える（`R.State.hasItem` が数える）。酒場の「装備をあずかる」で全部を道具袋へ移せる（`R.Rules.unequipAll`。99 個を超える品は外さずに残し、「持ちきれない品があった」と出す） |
| 個性 `innate` | 効かない |
| 宿屋 | 全快（出撃中と同じ） |
| 全滅したとき | 変わらない（全員全快で町へ。成長章 §12.2） |
| セーブ | CharState のまま `reserve` に入る（エンジン章 §4.1） |

### 5.5 酒場のマスターの台詞（どの酒場でも同じ。担当 newgame。地方の担当が別の台詞を足してもよい）
| 場面 | 文 |
|---|---|
| 話しかけたとき | `いらっしゃい。\n旅の仲間なら、ここで探せるよ。` |
| コマンド | `仲間を探す` `入れ替える` `並びと隊列` `装備をあずかる` `やめる` |
| 名簿に誰も残っていない | `名簿の旅人は、もう全員そろってるよ。` |
| 加入の確かめ | `{name}を仲間にするかい？`（はい／いいえ） |
| 装備をあずかる | `控えの{name}の装備を、すべて袋にしまうかい？`（はい／いいえ） |
| 出撃が満員で「加える」を選んだ | `出撃できるのは4人までだよ。` |
