# 03 世界・物語バイブル（DESIGN.md 用ドラフト）

この章は、世界設定・物語・地方・マップの**id と流れ**を決める。地方担当（reg-a / reg-b）、ワールド担当（world）、物語担当（story）は、この章の表をそのまま実装する。
魔物・装備・数値の中身は各章が決めるが、**id（ボスの編成、大事なもの、フラグ、目的、マップ、ゾーン）はこの章が正**。

- 文中の「必須」は、他の担当が依存する約束。変えるときは lead に報告する。
- 画面に出す台詞の例は、**そのまま使ってよい完成文**として書いた（1行20字以内、4行で1ページ）。物語担当は膨らませてよいが、固有名詞と筋は変えない。
- 主人公の名前は `{hero}`、先頭の人は `{leader}`。仲間の名前は台詞に出さない（どの3人を選んでも成り立つように、物語の台詞は主人公と固定キャラだけで組む）。

## 2. 大きな謎と真相

### 2.1 プレイヤーが最初に見る謎
- 世界中で、昔からの伝承が**人の記憶から消えていく**。歌の続きが出てこない、祭りの由来が分からない、碑文の文字が白く抜けている。人々はこれを「**白紙（はくし）**」と呼ぶ。
- 伝承が白紙になった土地では、その伝承が抑えていた災い（森の迷い、砂嵐、吹雪、霧、幽霊船……）が目を覚ます。
- 内海の中央のビブリア島は、いつからか**白い霧**に包まれ、船が近づけない。

### 2.2 真相（終盤で明かす。明かす順番は §2.4）
1. **虚ろの王**（真の名は**ネムレア**）は、世界に最初の物語が生まれる前からあった「忘却」そのもの。名も形もなく、名を持つものすべてを白紙に戻そうとする。
2. **千年前**、最初の語り部**フィーネ**は、世界で初めての物語「**始まりの年代記**」を書き、その力で虚ろの王を眠らせた。
   封印を保つために、年代記から**8枚のページ**を破り取り、8つの土地にそれぞれの伝承として預けた。
   **伝承が語り継がれる限り、ページは力を保ち、虚ろの王は眠り続ける**。始まりの年代記の本体は、のちに記録院の大書庫が建った場所（ビブリア島）に眠る。
3. フィーネは見張りを続けるため、自分自身を「伝承」として年代記に書き込んだ。人の姿をしているが、伝承が忘れられるほど体が薄れていく。
4. **二十年前**、エルセリアでは「どちらの伝承が正しいか」をめぐる**伝承戦争**が起き、記録院の学者ラザロは一人娘**ミラ**を失った。
5. 大書庫の奥で眠る虚ろの王の声を聞いたラザロは、「記憶こそが悲しみと争いを生む。すべてを忘れれば、戦争も悲しみも初めから無かったことになる」と信じた。
   虚ろの王に与えられた「**白の書**」は、書き写したものを人の心から消してしまう。ラザロは弟子の記録官たちに、各地の伝承を「保護のため」と言って白の書へ写させてきた。
   **各地方の事件は、記録官（ライバルのロウェルを含む）が伝承を写していったあとで起きている**。
6. ビブリア島の白い霧は、虚ろの王が目を覚ますまでのあいだ、ラザロが人を遠ざけるために張ったもの。**8枚のページがそろった光でしか払えない**。
7. 主人公が各地で伝承を語り直すと、人々が伝承を思い出し、ページがその土地の「伝承の核」から現れる。8枚がそろうと、ページの破れ目がつながって**虚ろの王の真の名**が読めるようになる。
8. 虚ろの王は「名を呼ばれること」＝物語になることで、初めて眠らせることができる。**最後に主人公が年代記にその名を書く**ことが決め手になる。

## 4. 年代記（物語の記録）の仕組み

- 年代記は主人公の本。メニューの「年代記」（menu 担当の `chronicleScreen`）で読む。大事なもの `k_chronicle` を持っていると開ける（序章の最後に受け取る）。
- 画面の中身（上から）：

  4. **ページ**：8枚の詩（§2.3）。
  5. **終章『語り部の旅』**（`final_open` で題と「（まだ書き終えていない）」、`game_clear` で要約。主人公自身の旅＝九つ目の伝承）、**外伝『円環の竜』**（`pg_clear`）

## 5. ワールドマップ

### 5.1 大きさと作り方
- **128列 × 112行**（クレストと同じ。地図の画面で1マス2ピクセル）。外周は3マス以上の海。
- `tools/gen_world.js`（world 担当）で生成する。クレストの生成器の仕組み（ノイズ・SDF・つながりの修復・ゾーンの矩形）を流用し、`LANDS` と `ICONS` を下の表で作り直す。`src/maps/world.js` は生成物（手で直さない）。
- 見た目はRS1風：街道（新タイル `road`）が町と町を結び、地方の境目は山並み・川・森で区切る。**ただし、どの地方にも序章のあとすぐ歩いて（諸島は定期船で）行ける**。山で道をふさいで順番を強制しない。

2. 階の出現位置：`from_prev`（前の階から来たとき＝前の階へ戻る階段の横）、`from_next`（次の階から戻ってきたとき＝次の階へ進む階段の横）。階段のワープは `{to:'<ダンジョン>_<n+1>', spawn:'from_prev'}` と `{to:'<ダンジョン>_<n-1>', spawn:'from_next'}`。
3. 全階に `escape:{to:'world', spawn:'<ダンジョンの1階の id>'}`。例外：千年樹は `verda_maze_1`、幽霊船は `{to:'nerei', spawn:'pier'}`、大書庫と忘却の底は `archive_1`（`{to:'world', spawn:'archive_1'}`）。
4. `type:'dungeon'`、`encounter:'<ゾーン>'`、`region:'<地方id>'`（序章は `'prologue'`、終盤 `'finale'`、裏 `'postgame'`）。
5. **ボスの部屋の手前**に「休息の灯」（調べると HP・MP・WP 全快。イベント `common_rest`、NPC id `rest`、絵 `obj:lantern`（新））を1つ置く。3階以上あるダンジョンは中ほどの階にもう1つ置いてよい。
6. ボスは見えるボス（NPC `boss`、絵 `mon:<ボスの絵>`、cond `'!<ボスのフラグ>'`）＋手前の step イベントの帯で始める（クレストの型）。負けたら全滅（`canLose` なし）。逃げられない。
7. ボスを倒したら、クリアの流れ（§8.0-4）。中ボスは倒すとフラグを立てて道が開く。
8. 宝箱の id は `<マップid>_c<n>`。中身はプール（`pool`）を基本にし、固定の品は装備の章の表に従う。**進行に必要な物は宝箱に入れない**（イベントで渡す）。

**大きさの目安**：町 40×32〜56×44。ダンジョンの階 32×32〜56×48（ボスの階はそれより小さくてよい）。1階の歩き回りは 5〜8 分。

## 8. 中盤の8地方（どの順番でも。約2〜2.5時間ずつ）

### 8.0 全地方に共通の約束（必須）
1. **地方の並び N（1〜8）**＝ファイル名 `src/maps/regionN_*.js`・`src/events/regionN_*.js` の番号。reg-a が 1〜4、reg-b が 5〜8。
2. **強さはティアで決まる**（どの順番でも崩れない）。地方の中で順番を強制するのは、その地方の中だけの鍵やフラグにする。**他の地方のクリアを条件にしない**。
3. **地方の流れ**：町に着く（onEnter で事件を知る、目的 `obj_<rs>_1` を設定）→ 手がかり → 中ボス → ボス → 伝承の語り直し → `ev.clearRegion(id)` → 町の宿で一晩（`ev.warp(<クリア後の町>,'inn')`＋`ev.heal()`＋キャプション「その夜は、町の宿で眠った。」）→ `await ev.call('story_after_clear')`（物語担当。§9.2）→ 町の人の台詞がクリア後に変わる。
   `<rs>` は地方の短い名前（`forest desert snow marsh isles mine ash star`）。
4. **ボス戦のイベント**（地方担当）：`await ev.battle('<troop>')` の結果が `'win'` でなければ `return false`（once を立てない）。勝ったら `<rs>_boss` を立てる。
5. **フィーネの場面**：ボスの部屋の手前（休息の灯のそば）に NPC `fine`（絵 `npc:fine`、cond `'!<rs>_boss'`）と、その手前の step イベント（once `<rs>_fine`）。台本 `story_fine_<rs>` は物語担当が書く（ティアで台詞が変わる。§9.4）。
6. **鍵の扉・閉じた道**：鍵や条件のいる所は「閉じたタイル」（通れないタイル。閉じた扉・氷の壁・つるの壁・封印など。art-tiles が用意する。§15）を置き、
   `tilePatches:[{cond:{item:'k_…'}, x, y, ch:'<開いたタイル>'}]`（鍵）や `tilePatches:[{cond:{var:'<名前>', gte:3}, …}]`（「3つ集める」型）で通れるようにする。
   閉じたタイルには examine イベントを重ね、理由を1〜2行で出す（例「分厚い氷の壁だ。\n火があれば、とかせそうだが……。」）。エンジンの `lock` 属性は使わない（鍵の id がタイルの定義に固定されてしまうため）。
7. **町の固定キャラの場所**（§9.2 の場面に使う。必須）：クリア後の町に NPC を3つ置く。どれも最初は出ない。
   - `st_rival`（絵 `npc:rowell`、cond `'st_show_rival'`）…出現位置 `inn` の2マス下、上向き
   - `st_fine`（絵 `npc:fine`、cond `'st_show_fine'`）…`inn` の2マス下・2マス右、上向き
   - `st_extra`（絵 `npc:scribe`、cond `'st_show_extra'`）…`inn` の2マス下・2マス左、上向き
   その3マスと、`inn` からそこまでのマスは歩ける床にし、ほかの物を置かない。クリア後の町は各地方の表の「クリア後の町」。
8. **噂の NPC**：各町に `folk_a` `folk_b`（`event:'story_rumor'`、`rumor:'<町id>_a'` / `'<町id>_b'`）を置く。台詞は物語担当が `DB.rumors` に書く（§9.3）。
9. **ティアで変わる台詞**：町の人の台詞は §4.4（エンジン章）の `{cond, text}` 配列で、少なくとも「クリア前」「クリア後」の2つを書く。
