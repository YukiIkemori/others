- 式と規則の正は次のとおり。この章はそれに合わせ、足りない所だけを足す（足したものは §0 と §3.4 に理由つきで書いた）。

- 閃きの格 `glim.lv` が、閃きの判定で使う「術の格（rank）」（成長章 §9.3 の `glim.lv ≤ rankB`）。`actions[id].rank` には同じ値を入れる（§3.1）。
- 「閃ける時期」= 普通の戦闘の閃きレベル rankB = ティア + 1 が `glim.lv` に届く時期。ボス（+2）・レア魔物（+2）・金色（+1）ではもっと早い。

### 1.4 閃きの条件（成長章 §9.3 の術の部分。規則）
術 s が候補になるのは、次の**すべて**を満たすとき。
1. その人が s を覚えていない。
2. s の属性の少なくとも1つが、いま使った術（または魔石）の属性に含まれる（合成術は、どちらかの属性の術を使えば閃くことがある）。
3. `s.glim.lv ≤ rankB`。
4. s の**すべての属性**で、熟練度の段階 `R.Rules.profRank(c.eprof[属性]) ≥ s.glim.prof`。
5. 3属性の術だけ: その3属性から作れる3つの組（例 火・光・闇 → 火光・火闇・光闇）のうち **2組以上で、その組の合成術（A か B）を1つ以上覚えている**。
- 候補の重み: 候補の中で `glim.lv` が一番小さいものは ×2、ほかは ×1。確率 p は成長章 §9.4。

## 3. データの形

### 3.1 `R.DB.actions[id]`（術の項目。エンジン章 §5.15 の形）
| 項目 | 型 | 意味 |
|---|---|---|
| `kind` | `'spell'` | 固定 |
| `name` | 文字列 | 全角 8 字まで（エンジン章 §1.7） |
| `desc` | 文字列 | 全角 20 字まで（半角は 0.5 字）。戦闘のヘルプ欄・術の書 |
| `elements` | `['fire', …]` | 1〜3 個、正式な並び順、重複なし |
| `cls` | `'single' \| 'comboA' \| 'comboB' \| 'triple'` | 段の種類。組み立て関数が付ける |
| `step` | 1〜5（単属性だけ） | 段の番号（術の書の表示用）。組み立て関数が付ける（装備・地方の「ティア」と混ざらないよう `tier` という名前は使わない） |
| `glim` | `{lv, prof}` | 閃きの格と必要な熟練度の段階（§1.3 の表のとおり。validate が検査） |
| `rank` | 数 | `glim.lv` と同じ値（エンジン章の表の `rank`）。組み立て関数が付ける |
| `order` | 数 | §2.2。組み立て関数が付ける |
| `mp` | 数 | 消費 MP（`R.Rules.mpCost` が `mpCostPct` をかける。最低 1） |
| `magic` | `true` | 固定（沈黙で使えない） |
| `target` | §3.2 | |
| `effects` | §3.3 の配列 | **書いた順に**1体ずつ実行する（クレストと同じ） |
| `quick` | `true`（任意） | 行動順の値 +10000（成長章 §5.2。防御と同じ組で最初に動く） |
| `field` | `true`（任意） | フィールドのメニューから使える（§3.5） |
| `fieldEffects` | 効果の配列（任意） | フィールドで使ったときは `effects` の代わりにこれを実行する |
| `noAuto` | `true`（任意） | オート戦闘・シミュレーターの AI が選ばない（今の 77 個には無い。将来用） |
| `fx` | 文字列 か 文字列の配列 | 演出（§3.4-7） |

### 3.3 効果 `effects[]`（術が使う型。成長章 §6・§8 の式で動く）
| type | 項目 | 働き（規則） |
|---|---|---|
| `damage` | `formula:'magic'`、`power`（= SP）、`hits?`、`drain?`、`ignoreMdef?` | 成長章 §6.2 の式。**属性は `action.elements`**（効果には `element` を書かない）。`hits` は1体に続けて n 回（`target:'random'` では選び直す回数）。`drain` は与えたダメージのその割合を使った人の HP に。`ignoreMdef` は術防を無視する割合 |
| `damage` | `formula:'percent'`、`power` | 相手の**今の** HP × power（最低 1）。ボス・鋼・レア魔物には効かない（「効かなかった！」）。属性の倍率はかけない |
| `heal` | `pct` | 相手の最大HP × pct × MNDF(使う人) × (1 + healPct/100)（成長章 §6.4）。生きている人だけ |
| `revive` | `pct` | 倒れた人を 最大HP × pct で生き返らせる（精神・healPct は効かない）。生きている人には何もしない |
| `cure` | `statuses:'all'` か `[…]` | 悪い状態（`statuses[s].bad === true`、即死を除く）を消す |
| `status` | `status`、`chance?` | **悪い状態**（と即死）: 成功率 p = chance × SF(使う人の知力) × (1 − 耐性)、0〜0.95（成長章 §8.3）。**良い状態**（`regen veil counter nimble`）: chance を書かない。必ずかかり、耐性を見ない。かかっていれば持続を付け直す |
| `buff` | `stat`、`stages`、`chance?` | 段階を足す（−2〜+2 に収める。成長章 §8.2）。**味方への強化**は必ず決まる。**敵への弱体**（stages < 0）: chance が無ければ必ず（ボスは 50%）、あれば chance × SF × (ボス ? 0.5 : 1)、上限 0.95。鋼には効かない。加護があれば防がれる |
| `dispel` | `side:'good' \| 'bad'` **（追加）** | `good`: 相手の正の段階をすべて 0 にし、良い状態（regen veil counter nimble）を消す。`bad`: 相手の負の段階をすべて 0 にする（悪い状態は `cure` で消す） |
| `healWp` | `pct` | 最大WP × pct 回復（生きている人） |
| `encounter` | `pct`、`steps` | フィールドだけ。`R.Game.encItem = {pct, steps}`（前の香・術の効果は置き換わる）。pct > 0 は「誘い寄せの香」と同じ扱い（レア魔物も2倍。成長章 §11.1） |
- 効果の順番は規則（例: 黄泉の門は 即死 → ダメージ なので、即死した相手にはダメージを与えない。倒れた相手には、それ以降の効果を実行しない。ただし `revive` は実行する）。
- 即死 `status:'death'` はボス・レア魔物・鋼に効かない（成長章 §8.1）。

### 3.4 追加した項目の定義（規則。rules・battle・bui・menu が実装する）
1. **`nimble` 身軽**（良い状態）: 持続 3手番。物理の命中の計算（成長章 §6.5）で、**受ける側の回避に +25** する（上限 60 は装備の回避だけにかかり、身軽の分は上限の外）。術・ブレス・固定ダメージには効かない。
2. **`dispel.side`**: §3.3。`side` を書かない `dispel`（クレストの形）は、相手が敵なら `good`、味方なら `bad` として扱う。
3. **効果の `on:'allies'`**: この効果は対象ごとのくり返しから外し、全員への処理が終わったあとに、**使った人の側の生きている味方全員**に1回ずつかける（例: 大地の目覚め＝敵全体にダメージ・まひ → 味方全員の守備力 +1）。`on:'self'` も同様（今は使っていない）。閃きの対象の向き（成長章 §9.2-5）は `target` で決め、`on` の効果は見ない。
4. **対象 `party`**: §3.2。戦闘では選ぶ画面を出さない。フィールドでも選ばない。
5. **`quick`**: 術にも付けてよい。閃きで置き換わった行動には効かない（すでに順番が来ているため）。
6. **`fieldEffects`**: §3.5。
7. **`fx` の配列**: 左から順に続けて出し、最後の演出の命中の時に数字を出す（エンジン章 §6 の「合成術（2つの fx を続けて出す）」の形）。1つ目以外は短く（1つ目の 60% の長さに）してよい。文字列は既存の fx の id（`fire ice thunder wind earth water holy dark explosion drain gravity death heal mp cure revive regen buff debuff dispel sleep poison …`、末尾の数字 1〜3 は大きさ）を**そのまま**書く（部分一致に頼らない）。`target:'random'` の術は1発ごとに配列全体を出す。
8. **閃いた術に対象が無いとき**: §0.12。battle の `useAbility` の前に `targets` を確かめる。

### 3.5 フィールドでの使用（規則。menu・field）
- `field:true` の術だけ、メニューの「技・術」から使える。MP を消費する（`R.Rules.mpCost`）。
- 実行する効果: `fieldEffects` があればそれ、無ければ `effects` のうち **`heal revive healWp cure`** だけ（ほかは読み飛ばす）。1つも効かなければ「使っても効果がない。」と出して MP を使わない。
- 対象の選び方: `ally` → 生きている人から選ぶ、`ally_dead` → 倒れた人から選ぶ（いなければ使えない）、`allies`・`party`・`self` → 選ばない。`fieldEffects` が `encounter` だけなら選ばない。
- 回復量はメニューも `R.Mon.healAmount` で計算する（エンジン章 §5.6）。
- `encounter` のメッセージ: pct < 0「魔物の気配が遠のいた。」、pct > 0「魔物の気配が近づいてきた……。」。効果が切れたとき（field が出す）「術の効き目が切れた。」。

### 3.6 戦闘のメッセージ（battle。クレストの形を使う）
- 唱えたとき「{name}は{術名}を唱えた！」。沈黙中は選べない（`unusable → 'silence'`）。
- 状態のメッセージは `R.DB.statuses[s].on`・`off`（§9.2）を使う（`{name}` を置き換える）。

## 4. 威力と知力

### 4.1 式（成長章 §4・§6.2 の再掲。正は成長章）
```
術力 mag = round((Wm + mods.mag) × (64 + 知力) / 64)      // Wm = 武器1・武器2の mag の大きい方（杖は 1.0 × W(T)、ほかの武器は 0.5 × W(T)、素手 4）
ダメージ = 術力 × SP × DK/(DK + 相手の術防 × (1 − ignoreMdef)) × 属性の倍率（術の属性のうち最大）× (1 + elemBoost/100)
         × 段階(自分 mag)/段階(相手 mdef) × (1 + magicPct/100) × (防御 ? 0.5 : 1) × rand(0.95, 1.05)
```
- **SP = `power`**。依頼文の「(power + 術力 × scale)」との対応は、足し算の部分 0・scale = SP（§0.3）。知力 1 あたりの伸びは「Wm/64 × SP」ぶん。
- 術は外れない。隊列の補正も無い。多段（`hits`）は1発ずつ計算する。
- 標準の魔物の術防は DK/2（成長章 §14.2）なので、術防の係数は**雑魚に 0.667、地方ボス（×1.2）に 0.625、裏ボス（×1.3）に 0.606**。

### 4.2 知力が効く3つの所（規則。成長章の式から）
| 知力 | 術力の倍率 (64+知力)/64 | 状態異常の成功 SF | 術の閃き GF | 例 |
|---|---|---|---|---|
| 16 | 1.25 | 0.86 | 0.77 | 戦士（知力の装備なし） |
| 52 | 1.81 | 1.07 | 1.01 | 術師 Z（知力の装備なし） |
| 112 | 2.75 | 1.43 | 1.41 | 術師 N（T8 の通常品で全身を知力に） |
| 232 | 4.63 | 2.00 | 2.00 | 術師 S（T8 の超レアで全身を知力に） |
- 知力を固めると、**威力（術力）・状態異常の決まりやすさ・閃きやすさ**の3つが同時に上がる。T8 で S は Z の 術力 2.55 倍・状態 1.87 倍・閃き 1.98 倍。
- 代わりに布の防具で物理を 1.43 倍受ける（成長章 §3.7）。
- 回復の量は知力ではなく精神（MNDF。§4.4）。「術師」でも攻めの知力型と、癒やしの精神型に分かれる。

### 4.3 SP の決め方（表の値が正。新しい術を足すときの式）
```
単体 1段 1.3 / 2段 1.6 / 3段 2.0 / 4段 2.5 / 5段 3.1      全体 2段 1.0 / 3段 1.1 / 4段 1.4 / 5段 1.7
合成A 単体 2.6・全体 1.45      合成B 単体 3.4・全体 1.9      3属性 単体 4.2・全体 2.4（大技 単体 4.5〜4.8・全体 2.7）
ランダム n 回（random）: 1発の SP = 単体の SP × 1.1 / n        1体に n 回（全体の多段）: 1発の SP = 全体の SP × 1.0 / n
単属性の割り引き: 30% 以上の状態・弱体 ×0.85、20% 以下の状態 ×0.92、吸収 30% ×0.92・50% ×0.88、先制 ×0.9、味方への強化の追加（on）×0.88
火のダメージだけの術（と、やけどだけの追加効果）: ×1.1（割り引きと打ち消し合う）
合成術・3属性: 割り引かない（状態は 合成A 30%・合成B 40%・3属性は効果 2〜3 つ。成長章 §6.6）
```

### 4.4 回復・蘇生・WP（成長章 §6.4）
```
回復 = 相手の最大HP × pct × MNDF × (1 + healPct/100)        MNDF = clamp((128 + 精神)/168, 0.75, 2.2)
蘇生 = 最大HP × pct（精神は効かない）        WP 回復 = 最大WP × pct
再生（regen）= 手番の終わりに 最大HP/10（5手番。魔物 /20）
```

|---|---|---|---|---|---|---|---|
| MNDF | 0.89 | 0.94 | 1.00 | 1.04 | 1.10 | 1.36 | 2.17 |
- 目安（成長章 §6.4）どおり: 単体の回復（ひだまり）0.35、全体（あまねく光）0.30、大回復（天の祝福）0.60＋加護、3属性の大回復（命の大樹）0.70。

## 5. MP の曲線

### 5.1 規則
- 各段の MP は §1.3 の範囲に入れる（validate が検査）。大技 4 つは 24（3属性の上限）。
- 表の MP が正。下の式は、新しい術を足すときと、シミュレーターの比べ方の目安。

### 5.2 式（目安）
```
ダメージの部分  MPd = 2 + 6 × (Deq − 1.3)       Deq = 単体 SP の合計 / 全体 SP の合計 × 1.8 / ランダム SP の合計 ÷ 1.1
追加効果        30% 以上の状態・弱体・吸収・先制 それぞれ +1、on の強化 +2
ダメージなし    単体の回復 pct p → 1 + 6p、全体の回復 → 1 + 20p、蘇生 p → 6 + 6p、
                味方1人の強化・良い状態 1つ 2、全員に 1つ目 5・2つ目から +3、敵全体の状態・弱体だけ 4 + 追加 1つ 2
最後に §1.3 の範囲に収める（例: 天の祝福は式で 18 → 5段の上限 14）
```
- 1 MP あたりのダメージは段が上がるほど下がり（1段 0.65 → 5段 0.24 → 大技 0.19 SP/MP）、**1回の行動の威力**が上がる。大技はボス戦で「ここぞ」に使うもの。

### 6.4 名前について
- どれもこの作品のための名前。ロマサガ・DQ・FF の術名・呪文名・技名は使っていない（一般の言葉「吹雪」「砂嵐」「地鳴り」などは使う）。
- 「恵みの雨」はクレストにもあった回復の術の名前（シリーズのつながり）。「三勇者の誓い」はクレストの伝説「紋章の三勇者」にちなむ（名前は出さない）。
- 漢字は常用の範囲で、画数の多い字はひらいた（よろい・とばり・いやし）。「黄泉（よみ）」「冥府（めいふ）」「極夜（きょくや）」は読める範囲とした。

**CODE 0 — 組み立て関数（3つのファイルの先頭に同じものを置く）**
```js
(function (R) {
  'use strict';
  const EL = ['fire', 'water', 'wind', 'earth', 'light', 'dark'];
  const GLIM = { 1: [1, 0], 2: [2, 2], 3: [3, 4], 4: [5, 6], 5: [7, 8], A: [4, 5], B: [6, 7], T: [8, 8] };
  const PAIRS = []; for (let i = 0; i < 6; i++) for (let j = i + 1; j < 6; j++) PAIRS.push(EL[i] + '_' + EL[j]);
  const TRIPLES = []; for (let i = 0; i < 6; i++) for (let j = i + 1; j < 6; j++) for (let k = j + 1; k < 6; k++) TRIPLES.push([EL[i], EL[j], EL[k]].join('_'));
  const dmg = (power, o) => Object.assign({ type: 'damage', formula: 'magic', power }, o || {});
  const pct = (power) => ({ type: 'damage', formula: 'percent', power });
  const st = (status, chance) => (chance == null ? { type: 'status', status } : { type: 'status', status, chance });
  const buff = (stat, stages, chance) => (chance == null ? { type: 'buff', stat, stages } : { type: 'buff', stat, stages, chance });
  const heal = (p) => ({ type: 'heal', pct: p });
  const revive = (p) => ({ type: 'revive', pct: p });
  const cure = (s) => ({ type: 'cure', statuses: s });
  const dispel = (side) => ({ type: 'dispel', side });
  const healWp = (p) => ({ type: 'healWp', pct: p });
  const enc = (p, steps) => ({ type: 'encounter', pct: p, steps });
  const onAllies = (e) => Object.assign({}, e, { on: 'allies' });
  // cls: '1'..'5' = 単属性の段、'A' / 'B' = 2属性、'T' = 3属性
  function sp(name, elements, cls, mp, target, effects, fx, desc, o) {
    const [lv, prof] = GLIM[cls];
    const key = elements.join('_');
    const order = elements.length === 1 ? 10 * (EL.indexOf(elements[0]) + 1) + Number(cls)
      : elements.length === 2 ? 100 + 2 * PAIRS.indexOf(key) + (cls === 'A' ? 0 : 1)
      : 200 + TRIPLES.indexOf(key);
    const a = { kind: 'spell', magic: true, name, desc, elements, mp, target, effects, fx,
      cls: elements.length === 1 ? 'single' : elements.length === 3 ? 'triple' : cls === 'A' ? 'comboA' : 'comboB',
      glim: { lv, prof }, rank: lv, order };
    if (elements.length === 1) a.step = Number(cls);
    return Object.assign(a, o || {});
  }
  Object.assign(R.DB.actions, {
    // ↓ CODE 1 / CODE 2 / CODE 3 の中身
  });
})(window.RPG);
```

## 10. 閃きの実装（`src/systems/glimmer.js`。式の正は成長章 §9、API の正はエンジン章 §5.7）

```js
R.Glimmer = {
  classOf(a) → 'tech' | 'single' | 'comboA' | 'comboB' | 'triple'   // a = DB.actions の項目。術は a.cls、技は 'tech'
  candidates(c, ctx) → [{ id, w, p }]                              // 候補・重み・確率（デバッグとシミュレーター用）
  chance(c, id, ctx) → p
  roll(c, ctx) → { id, kind: 'tech' | 'spell' } | null             // c を変えない。乱数は ctx.rng || R.U の関数
  learn(c, id) → bool                                              // エンジン章 §5.7 のとおり
}
ctx = { kind: 'tech' | 'spell', wtype?, elements?: [...], used: actionId | 'attack', stone?: bool,
        rankB, ef, tier, rng? }                                      // rankB・ef は戦闘の開始時に Engine が決める（成長章 §9.2）
```
**術の部分の手順（規則）**
1. 候補: `DB.actions` のうち `kind === 'spell'` で、§1.4 の 1〜5 を満たすもの。5 の「組の合成術を覚えている」は `c.spells` の中に `elements.join('_')` がその組と同じ術があるか、で数える。
2. 重み: 候補の中の最小の `glim.lv` と同じものは 2、ほかは 1。重みで1つ選ぶ。
3. 確率:
```
p = BASE[cls] × APT × GF × FK × EF × MARGIN × (1 + glimPct/100)、上限 0.35
BASE = { single: 0.015, comboA: 0.012, comboB: 0.010, triple: 0.008 }        // R.Rules.K.GLIM.base
APT  = 候補の属性ごとの R.Rules.aptitude(c).e[属性] の平均                   // S 2.0 A 1.5 B 1.0 C 0.6 D 0.3
GF   = clamp((100 + stats(c).int)/150, 0.7, 2.0)
FK   = clamp(1 + 0.4 × (EXPECT[tier] − (c.techs.length + c.spells.length) − 2), 1, 4)
EF   = ctx.ef       MARGIN = 1 + 0.1 × min(5, rankB − glim.lv)
glimPct = mods.glimPct の、候補の属性の値の最大 ＋ mods.glimPct.spell
魔石の入口: ctx.stone で、c が ctx.elements[0] を含む術を1つも覚えていなければ p × 10（上限 0.35 のまま）
```
4. 1回の行動につき判定は1回（成長章 §9.2）。当たったら battle が `learn` → 行動の置き換え（§0.12 の例外あり）。
- 定数は `R.Rules.K.GLIM`（成長章 §18.1）から読む。glimmer.js に数字を書かない。
- `R.Glimmer` は技の閃き（`kind:'tech'`）も同じ関数で扱う（技の候補の規則は成長章 §9.3。技章のデータの `glim.from` を読む）。

## 13. validate に足す検査（担当 qa。術の部分）
1. `s_` の id が §0.2 の形で、`elements` と一致する（並び順・重複なし）。77 個ちょうど。15組それぞれに A と B、20組それぞれに1つ。単属性は 火・光・闇 が 1〜5、水・風・土 が 1・2・3・5。
2. `glim` が §1.3 の表どおり（`cls` と `elements` から決まる値）。`rank === glim.lv`。`mp` が §1.3 の範囲。
3. 名前 8 字以内・desc 20 字以内（エンジン章 §1.7）。技・術・魔物の行動で表示名が重ならない（魔物は §0.13 の例外だけ）。
4. `effects` の型が §3.3 の表にある。`status` の id が `DB.statuses` にある。良い状態に `chance` が無い。`buff.stat` が `atk def mag mdef agi`、`stages` が −2〜+2。`scale`・`element`・`metalHit`・`escape` を術に書いていない（§0.3・§0.10・§0.11）。
5. `target` が §3.2 の表にある。`random` なら `damage.hits` がある。`on` は `'allies'` か `'self'`。
6. `field:true` なら、§3.5 で実行できる効果が1つ以上ある（または `fieldEffects` がある）。
7. `fx` が既存の fx の id（数字 1〜3 つき可）か、その配列。
8. キャラ章の `startSpells` がすべて 1段の術。魔物の `actions` に `s_` が無い。
9. check_text: 名前・desc に使ってはいけない名前（サガ・RS2 の技名と術名・DQ/FF の呪文名や魔物名）が無い。
