## 1. エンジンの作り

### 1.1 解像度と画素の約束

- 実キャンバスは今のまま **1024×896**、論理 256×224、`R.SCALE = 4`（`ns.js`・`gfx.js` の既存の約束は変えない）。
- **HD の画素（art px）= 2 デバイス px = 0.5 論理 px**。戦闘の画面は 512×448 art px の格子。試作 2 回目と同じ（`scenes2.js` の `K = 2`）。
  - 4 デバイス px の今のドット（1 論理 px）より 2 倍細かい。試作で「滑らか寄り（1 デバイス px の画素、4 倍解像度）」は粘土細工に見えて却下されたので、**これ以上は細かくしない**。
  - 絵はすべて **最近傍（`imageSmoothingEnabled = false`）で整数倍**に描く。例外は焼き込んだ「ぼけた層」（遠景・手前のぼかし・光・影）だけで、これは半分の解像度で焼いて滑らかに拡大してよい。
- 置く位置は論理座標で **0.5 刻み**（= 1 art px）。0.5 未満の端数は丸める（画素が泳がない）。
- 文字は今と同じく実解像度で描く（`Gfx.text`）。

### 1.2 `R.Hd` — 新しい描画の土台（担当 HD-CORE、`src/art/hd/a_core/*.js`）

今の `R.Gfx` はそのまま残し、HD の絵は新しい名前空間 `R.Hd` で扱う。**P1 のあいだは `gfx.js` を変えない**（`R.Hd` は `R.Gfx.ctx` を関数の中で読むだけ）。P2 で `gfx.js` に入れるのは §7.3 の小さな差分だけ。

| API | 中身 |
|---|---|
| `R.Hd.RZ` | 試作 `raster.js` を移したもの（`Builder`・`mat`・`render`・`ramp`・`vnoise`・`rng`・`hex`・`mix`）。`render(B, {scale, flip, light, tones, sat, olMix, tint})` は art px の canvas と原点 `ox, oy` を返す。 |
| `R.Hd.RIG` | 試作 `rig.js` を移したもの（骨組み・ポーズ・補間・髪の殻・`headScale`）。§2 の決まりの本体。4 方向（§4.2）は HD-RIG が足す。 |
| `R.Hd.def(key, factory, meta)` / `R.Hd.get(key, opts)` | HD の登録簿。キーは `hd:party:<look>`・`hd:npc:<type>`・`hd:mon:<sprite>`・`hd:boss:<sprite>`・`hd:bbg:<id>`・`hd:tile:<theme>:<id>`・`hd:decor:<id>`・`hd:obj:<id>`・`hd:icon:<id>`・`hd:bfx:<id>`。factory は **Sheet**（下）を返す。未登録は `R.Hd.has(key) === false`（呼ぶ側が今の絵に戻る）。 |
| **Sheet** | `{ px: 0.5, frames: [{c: canvas, ox, oy}], poses: {name: [frameIndex…]}, hold: {name: [frames]}, anchors: {feet, head, hand, center, fx}, w, h }`。`w h ox oy` と anchors は**論理 px**（art px ÷ 2）。1 枚絵は frames が 1 つ。 |
| `R.Hd.draw(frame, lx, ly, opts)` | 論理座標 `lx, ly`（原点 = 足もとなど frame の `ox, oy`）に、0.5 刻みに丸めて描く。`opts = {flip, alpha, tint: '#rrggbb', tintAmt, scale}`（`scale` は 1・0.5 など、焼いた大きさからの縮小だけ。拡大は焼き直す）。 |
| `R.Hd.bake` | 焼く仕事の列（§1.4）。`R.Hd.bake.want(key, opts, priority)`・`R.Hd.bake.pump(budgetMs)`・`R.Hd.bake.ready(key, opts)`・`R.Hd.bake.now(key, opts)`（同期で焼く。場面の切り替えの暗転中だけ使う）。 |
| `R.Hd.cache` | LRU。上限は画素数（既定 **2400 万 art px ≈ 96 MB**、`R.Hd.cache.limit`）。場面ごとの「固定」（今の戦闘の 4 人・今の敵・今の背景）は追い出さない。 |
| `R.Hd.blur(canvas, r)` | stack blur（JS）。`ctx.filter` を使わない。 |
| `R.Hd.mood` | 光の場面の表（§1.5.2）と色調の LUT（`R.Hd.grade(canvas, moodId)`）。 |
| `R.Hd.quality()` | `R.Settings.fx`（`'high'|'low'|'off'`）を返す。P1 のあいだは `R.Hd.QUALITY_OVERRIDE` か `'high'`。 |
| `R.Hd.PENDING` | まだ描いていない HD の id（`push` で足す。§11.1.3 と同じ決まり）。 |

ファイル（読み込み順は `build.js` の `walk` の辞書順。`src/art/hd/` は `src/art/` の中で `decor*`・`faces.js` の後、`monsters*` の前に入る）:
- すべての HD のファイルは今と同じく IIFE で**登録だけ**を行い、他のファイルの物は**関数の中でだけ**読む。
- ディレクトリの頭の文字で順番を固定する: `a_core/`（HD-CORE）→ `b_rig/` → `c_cast/` → `e_mons/` → `f_boss/` → `g_rare/` → `h_bbg/` → `i_tiles/` → `j_decor/` → `k_ui/`。`a_core` の中は `a_core/rz.js`・`a_core/hd.js`・`a_core/bake.js`・`a_core/post.js`・`a_core/mood.js`。

### 1.3 焼く大きさ（何を何 art px で持つか）

| 物 | 焼く大きさ | コマ数 | 1 コマの焼き時間（試作の実測、デスクトップのヘッドレス Chromium） |
|---|---|---|---|
| 戦闘の味方（1 人・1 系統の武器） | 全高 約 60 art px（`scale 1.12`、論理 30 px。A8 の目安 24〜32 px） | 15 ポーズ・34 コマ（今の `R.Art.BATTLER` と同じ表） | 4.1 ms |
| フィールドの人物（味方 30・NPC 47） | 全高 1.5 タイル（§1.7 の `d` による。ひろい: 36 art px） | 4 方向 × 3 コマ = 12 | 約 2 ms |
| 小さい魔物（S・M） | 高さ 40〜80 art px | 待機 2 ＋ 攻撃 1 ＋ 被弾 1 = 4 | 5 ms（スライム） |
| 大きい魔物（L） | 80〜112 art px | 4 | 15 ms（氷狼 1.55 倍） |
| ボス | 130〜240 art px | 4〜6（部位の動き） | 30〜80 ms（見込み） |
| 戦闘背景 | 512×448 の層 3〜4 枚 | 1（水・炎・雪などの動きは小さな重ね絵で） | 200〜400 ms（見込み。地面の模様の画素生成が主） |
| タイル | 1 タイル `16·d` art px 四方 | 1（水などは 4） | 0.3〜1 ms |

- スマホは**デスクトップの約 4 倍遅い**と見て予算を組む（§7.5 で `CPUThrottlingRate 4` で測る）。
- 戦闘の遠近: 味方の 4 か所・敵の並びは**場所が決まっている**ので、**遠近の大きさは「場所の段」ごとに 1 つ**に固定して焼く（試作のように位置ごとに焼き直さない）。味方は 4 段（前列・後列 × 上下）のうち、実際は 1.0 と 0.94 の 2 種。踏み込みで前に出ても大きさは変えない。敵は前列 1.0・後列 0.92 の 2 種。

### 1.4 焼く仕事の列と読み込みの予算

焼く順番（優先度が高い順）と、いつ焼くか:

| いつ | 焼く物 | 予算（スマホ見込み） |
|---|---|---|
| 起動〜タイトル | 何も焼かない（タイトルの絵だけ） | 追加 0 |
| 主人公の作成・仲間選び | 表示する人のフィールドの絵（見える分から） | 1 人 50 ms、見える順に列で |
| マップに入る（暗転中） | 見える範囲のタイルと飾り（今の `field.js` の whole-map キャッシュと同じ）、4 人のフィールドの絵、そのマップの NPC | 暗転 0.3 秒の中で 300 ms まで、残りは列で |
| フィールドを歩いている間（**1 フレーム 3 ms まで**、`R.Hd.bake.pump(3)`） | ① 4 人の戦闘の絵（今の武器・待機と攻撃のポーズを先に） ② そのマップの出現表（`DB.encounters` のゾーン）の魔物 ③ そのゾーンの戦闘背景 ④ マップの残りのタイル | 1 フレーム 3 ms（60 fps を割らない） |
| 戦闘の開始（ワイプの 0.5 秒） | 焼けていない物だけ `bake.now`。**背景 → 敵の待機のコマ → 味方の待機**。攻撃などのポーズは戦闘中に列で（焼けていないポーズは一番近い焼けたポーズで代用） | 500 ms まで |
| 装備を替えた・仲間を替えた | その人の戦闘の絵を列の先頭に | 列で |

- キャッシュの持ち方は §1.2 の LRU。戦闘の味方の絵（4 人 × 34 コマ × 約 60×70 art px）は 約 2.3 MB、背景 1 種は 約 3 MB。
- **P3（任意）**: IndexedDB に焼いた絵を持ち越す（キー = `ART_VERSION` ＋ キー ＋ opts）。2 回目の起動からはほぼ 0 で読める。`ART_VERSION` はビルドで `src/art/hd/**` のハッシュから作る。
- 焼いたコマは必ず**同じ乱数の種**から作る（同じキーなら毎回同じ画素）。テストで比べられる。

### 1.5 戦闘の効果の作り（試作 2 回目の見た目を、スマホで出す）

#### 1.5.1 層の順番（下から）

| # | 層 | 作り方 | 焼く／毎フレーム |
|---|---|---|---|
| L0 | 空・雲・遠景の崖・中景（もや、ぼかし 2〜5 px、色調） | 背景の生成器が 3 層を描き、`R.Hd.blur` でぼかし、もやと色調を掛け、**1 枚にまとめる**（半分の解像度 512×448、滑らかに拡大） | 焼く（戦闘背景 1 種につき 1 回） |
| L1 | 遠近の地面（手前ほど模様が大きい、戦う場所の踏み固めた土） | 地面の座標で模様を作って投影（試作 `groundLayer`）、地平の縁は L0 へ溶かす | 焼く（512×448、くっきり） |
| L2 | 太陽の光・光の筋・もやのベール | 加算（`'screen'`/`'lighter'`）の 1 枚に焼く | 焼く |
| L3 | 落ち影（長い影）＋足もとの影 | **コマごとに**スプライトの影絵を斜めに伸ばしてぼかした影を、スプライトと一緒に焼く（影の向きは場面の光 §1.5.2） | 焼く（コマと一緒）、描くのは毎フレーム |
| L4 | 敵と味方のスプライト | Sheet のコマ（くっきり） | 毎フレーム |
| L5 | 技・術の効果 | 今の `battle_fx.js` の効果を HD の効果の絵（`hd:bfx:*`）に置き換え。光る物は**前もってぼかした光の絵を加算で重ねる**（ブルームの代わり） | 毎フレーム |
| L6 | 手前のぼけた岩・草（被写界深度） | 焼く（半分の解像度） | 焼く |
| L7 | 光の粒（ゆっくり漂う） | 30〜60 粒の小さな光の絵 | 毎フレーム（高のときだけ） |
| L8 | 周辺減光＋色調の仕上げ | 周辺を暗くするグラデーションと色の膜を 1 枚に焼く（`'multiply'` 1 回） | 焼く（場面の光ごと） |
| L9 | UI（細い半透明） | 文字は実解像度、窓は細い線と半透明の帯 | 毎フレーム |

- 1 フレームの `drawImage` は 背景 3 枚＋スプライトと影 各 4〜10＋効果＋手前 1＋仕上げ 1。**予算: デスクトップ 3 ms、スマホ見込み 10 ms 以下**。
- **スプライトの色調**（暖色の影、場面の色）は、焼いたコマに **LUT を掛けたもの**を場面の光ごとにキャッシュする（2 段のキャッシュ: ①ラスタライズ（重い、光に依らない）→ ②色調（軽い、1 コマ 0.1 ms））。場面の光が変わってもラスタライズはやり直さない。
- 点光源（松明）でスプライトが照らされる試作の表現は、戦闘では使わない（色調とリムの色で代える）。フィールドの夜の灯りは §1.7 の光の層で出す。

#### 1.5.3 効果の設定（`Settings.fx`）

| 設定 | 見た目 | 中身 |

| **高**（既定） | 試作 2 回目と同じ | L0〜L9 すべて。光の粒・加算の光・灯りのゆらぎ・フィールドの光の層。 |

#### 1.5.4 WebGL について

### 1.7 見下ろしのフィールド（町・ダンジョン・ワールド）の質上げ（追記3 の「B」）

**変える物**:
1. **タイルの解像度**: 1 タイル = 16 map px は同じ。絵は **`d` art px / map px** で生成する（生成器は map px の連続座標で書き、`d` で画素に落とす。試作のラスタライザも模様のノイズも倍率に依らない）。

   | フィールドの広さ | z（デバイス px / map px） | d（art px / map px） | 1 art px | 1 タイルの絵 |
   |---|---|---|---|---|
   | ふつう | 4 | 2 | 2 デバイス px | 32×32 |
   | ひろい（既定） | 3 | 1.5 | 2 デバイス px | 24×24 |
   | もっとひろい | 2 | 2 | 1 デバイス px | 32×32（細かい画素。遠くから見た形） |

   「ふつう」と「ひろい」は戦闘と同じ画素の大きさ（2 デバイス px）。広さを変えたらタイルのキャッシュを焼き直す（今も広さでキャッシュを作り直している）。
2. **色**: §2.1 の決まり（落ち着いた彩度・素材ごと 3〜5 段・暖色の影・色つきの縁）。テーマの色の表（今の `THEME_DEFS` の色）を HD-TILES が新しい段に作り直す。DESIGN §11.0 0.1 の「RS1 寄りの落ち着いた地面」は続ける。
3. **陰影**: 壁・屋根・木・岩・柵は 2.5D のラスタライザで立体に（面ごとの光、面取り、AO）。床の模様（石畳・板・土・草）は画素生成（試作 `places.js` の石畳・石積み・木組み）。
4. **光と影の層**（新しい、`field.js` の P2 の差分）:
   - **環境光**: マップごと `map.light = {ambient: '#rrggbb', k: 0..1}`（町の昼 1.0、屋内 0.85 暖色、ダンジョン 0.55〜0.7、夜の町 0.45 青）。無ければテーマの既定（HD-TILES が `hd:theme:<id>.meta.light` に書く）。

5. **人物**: フィールドの人物（味方 30・NPC 47・動物）は §4.2 の骨組みの 4 方向で作り直す（今の 16×24 の手描きのドットは使わない）。

## 2. 絵の決まり（スタイルバイブル）

### 2.1 色

- **素材ごとに色の段（ランプ）を持つ**。鍵の色 5〜6 個（暗 → 明、色相をずらす）から作り、画面に出るのは **3〜5 段**（`STYLE.tones = 5` で量子化）。同じ素材に 6 段以上の色を出さない。
- **彩度を抑える**: 服・革・木・石・地面は HSV の S ≤ 0.55、明るい段ほど彩度を下げる。**強い彩度は小さな所だけ**（宝石・魔法の光・目・レアの印・状態の印）で S ≤ 0.8。全体の仕上げで `sat 0.9`（魔物は `0.78`）。
- **色相のずらし**: 影は暖かい紫・茶へ（青い影にしない。夜と氷の場面だけ青へ）、明るい所は暖かい黄へ。
- **縁取りは黒にしない**: 外周の 1 art px の縁は「その画素の素材の一番暗い段を、暗い色に 82% 寄せた色」（`olMix 0.82`）。純粋な `#000` は**使わない**（検査 §7.5）。部品どうしの境は縁ではなく**重なりの陰の線（AO）**で分ける。
- 明るさの目安: 人物の顔の明るい段 `#f4d8c0` を画面の一番明るい肌とし、服の一番明るい段はそれより暗く（主役は顔と武器の光）。
- 金色の個体（魔物）は今と同じく `tint`（明るさを保って金へ）。レアはキラキラ（今の演出）。鋼の魔物は金属の素材（映り込みの帯・点光）で描く（色替えではなく素材替え）。

### 2.2 形と頭身

- 人物は**全高 約 56 単位（scale 1）、頭（髪を除く頭蓋）約 20 単位 → 2.6〜2.8 頭身**。試作の頭を **0.88 倍**にした（`headScale`、首の付け根を中心に頭・顔・髪をまとめて縮める）。見本 `out/sheet2_headscale1_compare.png`（1.0 倍）と `sheet2_party_poses.png`（0.88 倍）。
- 戦闘の大きさ: `scale 1.12` → 全高 約 60 art px（論理 30 px）。フィールド: 全高 1.5 タイル（24 map px）。
- 体の型: 性別 2 × 体格 3（`slim` `normal` `sturdy`）× 背 3（`0` `short` `youth`）。今の `R.Art.BATTLER.LOOK` の表をそのまま使う。
- 目は 2 つとも見える斜め横顔（手前の目が大きい）。口・頬の赤み・眉は 1〜2 art px。表情はポーズの `eyes` `mouth` `sq`（閉じ目・叫び・食いしばり）で切り替える。
- 服の型: `tunic` `armor` `robe` `coat` `gi` `light` `dwarf` `hakama`（今のフィールドの体の型と同じ 8 種）＋ マント `mantle` `long`、フード、鎧の肩当て・胸当て。

### 2.3 髪（オーナー指摘「耳が大きい・剃り込み・後頭部まではげ」への決まり）

試作 `rig.js` の `hair()` の**髪の殻（`hairshell`）**を全員に使う:
1. **髪は頭の手前の層で、顔以外を全部覆う**: 頭頂・側頭・耳・後頭・うなじ。頭の座標で、顔の前の縁（x ≈ 0.5、目のすぐ後ろ）から後ろはすべて髪。うなじは首の付け根まで下りる（`nape 9.4`）。
2. **もみあげ**: 殻の前の縁は目の後ろで下り、顎の高さ（`burn 5.2`）で細い毛先になる。短髪でも必ずある。
3. **耳は髪の下**（描かない）。見せるのは `ears: 'show'`（小さな 1.2×1.7）、髪なしの人（`hairStyle: 'none'`、坊主・禿げの NPC）、エルフの耳（殻の上に細く短く）だけ。**大きな肌色の耳を出さない**。
4. 殻の上に**毛の溝**（fold 3 本）と**毛先**（strand 3 本）を付け、ヘルメットに見せない。髪型（とげ・三つ編み・長い・ボブ・ポニー・おだんご…）の毛束は殻の上と後ろに足す。
5. 帽子・兜・フードは殻の上にかぶせる。兜の下からも、もみあげとうなじの髪が少し見える。
6. **検査**（§7.5 `tools/hd_check_hair.js`）: 全員を 待機・被弾・勝利・4 方向で焼き、頭の後ろ半分（顔の前の縁より後ろ・頭頂から顎まで）の画素のうち**肌の色が 8% 以下**であること。落ちた人は一覧に出る。
7. 見本: `out/sheet2_heads_zoom.png`（直した後）。直す前は `out/sheet_party_poses.png` の古い版（NOTES §6 に経緯）。

### 2.4 光

- 主光は場面の光（§1.5.2）。スプライトは焼くときに**主光 1 つ＋環境光**で陰を付け（ラスタライザの法線）、**背中側から暖色のリムライト**（`rimC #ffd8a0`、`rimK 1.25`、1 art px）。逆光の場面ほどリムを強く。
- 金属は映り込みの帯と点光、髪はつやの帯（`sheen`）、布は布目、革は皺のノイズ。**ノイズは部品の座標に固定**（動いても模様が泳がない）。
- 戦闘の味方は左向き（右向きに描いて `flip`）。**光と影は反転の後に付ける**（焼くときに `flip` を渡す。影が左右で逆にならないこと）。

### 2.5 魔物の向きと大きさ

- **すべての魔物・ボスは右向き**（顔・体の前が +x。味方の方）。斜め 3/4 の横向きで、手前の目・手前の脚が大きい。正面向きの絵は作らない（浮遊する目玉・本・水晶のように前後の無い物は、光と影で右を向いて見せる）。
- 大きさの段（**表示の高さ、論理 px**）。`enemyLayout` はこの段で並べる:

  | 段 | 高さ | 例 | 今の絵 |
  |---|---|---|---|
  | S | 16〜26 | ゼリー・ネズミ・コウモリ・妖精・鬼火 | ≤32 の 63 体 |
  | M | 26〜40 | 狼・小鬼・骸骨・カニ・キノコ | 33〜48 の 113 体 |
  | L | 40〜60 | 熊・ゴーレム・ワイバーン・巨人の子 | 49〜64 の 35 体 |
  | 中ボス・追加（add） | 40〜80 | 人形・触手・分身 | 48〜96 |
  | 地方ボス | 70〜100 | 白竜・溶岩の巨獣・星食らい | 96〜112 |
  | 最後・裏 | 90〜120（画面の上へはみ出してよい） | 虚ろの王・ネムレア・オウロボラ | 128×112 |

- 同じ系統の段（`lineages` の 1〜5 段）は段が上がるほど少し大きく（+0〜15%）、部品が増える。色だけの違いにしない（今の A14a の決まりのまま）。
- 魔物の動き: 待機 2 コマ（呼吸・羽ばたき・揺れ）＋攻撃 1 コマ（前へ伸び）＋被弾 1 コマ。今の揺れ・踏み込み・逃げの動き（`battle_scene` の `shake` `lunge` `dodge` `flee`）はそのまま使う（向きは右 → 攻撃は +x、よけるのは −x。今と同じ）。

### 7.2 呼ぶ側の形（P2 で変える所）

- 戦闘: `R.Art.battler(who, opts)` → `R.Hd.has('hd:btl:…') ? R.Hd.get(…) : 今の絵`。Sheet の `px: 0.5` を見て `R.Hd.draw` で描く。`frameOf`・`posOf`・アンカー（head hand feet）の使い方は今の SV-ART の約束と同じ。影は Sheet の `shadow` のコマを先に描く。
- 魔物: `mon:<id>` の代わりに `hd:mon:<sprite>`（無ければ今の絵）。`enemyLayout(list, sizeOf)` の `sizeOf` は Sheet の論理 `w h` を返す。
- 背景: `drawBackdrop` は `hd:bbg:<id>` の層（`back`・`front`・`post`）を順に描く（§1.5.1）。
- フィールド: タイル・飾りのキャッシュを作る関数だけを `R.Hd` の生成器に差し替え（`d` を渡す）。光と影は、キャッシュのチャンクを作った直後に同じチャンクへ焼く。人物は `hd:party:<look>` / `hd:npc:<type>` の Sheet（4 方向 × 3 コマ）。
- メニュー: 顔は `hd:face:<look>`。

### 7.3 エンジンの差分（GFX、P2）

- `gfx.js`: `Gfx.drawHd(frame, x, y, opts)`（= `R.Hd.draw` を呼ぶ薄い口）、`Gfx.reset()` で `imageSmoothingEnabled` を戻す所に HD の層の後始末を 1 行。
- `save.js`: `DEFAULT_SETTINGS.fx = 'high'`、`settingsVer` を 1 上げ、古いセーブは `'high'`。デバッグの `art: 'hd'`。
- `engine.js`: 1 フレームの終わりに `R.Hd && R.Hd.bake.pump(場面に応じた ms)`（フィールド 3 ms、戦闘 1 ms、メニュー 4 ms、暗転中 12 ms）。
- `ns.js`: 変えない（`R.W R.H R.SCALE` はそのまま）。

### 7.4 古い絵の撤去（P3、QA-HD）

### 7.5 確かめ方

**一覧表（各担当、P1 から）**: `node tools/hd_sheet.js --area <cast|mons|boss|rare|bbg|tiles|decor|ui> [--only id,…] --out <自分のスクラッチ>` で、
(a) **1:1**（実際の画面と同じ 2 デバイス px の画素）と (b) **×4 の拡大**の 2 枚を必ず撮り、**Read で見る**。人物は 待機・前進・振りかぶり・斬る・詠唱・被弾・膝つき・戦闘不能・勝利 と 4 方向、魔物は 4 コマと 3 つの場面の光（day・cave・night）で。

**自動の検査（`tools/hd_check.js`、HD-CORE が作り、全員が通す）**:
- 純粋な黒 `#000000` の画素が 0（縁は色つき）。
- 素材ごとの色の段の数 ≤ 5（焼いたコマで、同じ素材の画素の色を数える）。彩度の上限（§2.1）を超える画素が、宝石・魔法の印の範囲の外で 2% 以下。
- 魔物の向き: `anchors.head` の x が胴の中心より右（右向き）。ボスも。
- 髪（`hd_check_hair.js`）: §2.3 の 6。
- 同じキーなら同じ画素（2 回焼いて比べる）。
- 大きさの段（§2.5）に入っていること。

**画面（P2）**: `node tools/build.js && node tools/shot.js …` で、
- 1024×896（1:1）: 通常戦闘・ボス戦（大きいボス）・閃きの瞬間・術の詠唱・全員の勝利ポーズ・後列の配置・瀕死と戦闘不能（A8 と同じ 7 枚）、町の昼と夜、屋内、ダンジョン（松明）、ワールド、メニュー。効果の 高・低・切 の 3 通り。
- **スマホの大きさ**: Playwright の端末の真似で 縦 390×844（DPR 3）と 横 844×390。文字の読みやすさ（5 字の名前・999/999）と、細い UI が潰れないこと。
- 変更前（今の絵）と並べた比較の画像（`tools/compare_shots.js`）。

**性能（`tools/hd_perf.js`、QA-HD、P2 から）**:
- 焼く時間: 種類ごとの 1 コマの平均と最大、戦闘の開始の待ち（焼けていない場合と、列で焼き終えた場合）、マップに入るときの待ち。
- 1 フレームの描画時間: 戦闘で 600 フレーム（効果の多い術を含む）の平均と 95%、フィールドで歩き回る 600 フレーム。
- 目標（デスクトップ ／ `Emulation.setCPUThrottlingRate 4` でスマホの見込み）:
  | 項目 | 目標 |
  |---|---|
  | 戦闘の 1 フレーム（高） | 平均 3 ms ／ 10 ms、95% 5 ms ／ 14 ms |
  | フィールドの 1 フレーム（高、灯り 10 個） | 平均 2 ms ／ 8 ms |
  | 戦闘の開始の待ち（列で焼き終えた後） | 50 ms ／ 200 ms |
  | 戦闘の開始の待ち（何も焼けていない最悪） | 400 ms ／ 1.5 s（暗転を延ばして隠す） |
  | マップに入るときの待ち | 150 ms ／ 500 ms |
  | 焼いた絵の合計（画素 × 4 バイト） | 150 MB 以下 |
- 目標を超えたら: 効果の設定の自動の下げ（§1.5.3）を先に確かめ、それでも超えるなら、背景の層を 1 枚にまとめる・影を半分の解像度にする・コマ数を減らす（待機 2 → 1）の順で削る。

## 付録 B. 用語

- **art px**: HD の絵の 1 画素 = 2 デバイス px = 0.5 論理 px。
- **焼く（bake）**: コードで絵を描いて canvas に残すこと。以後は `drawImage` だけ。
- **Sheet**: 1 つの絵のコマと原点・アンカーの束（§1.2）。
- **mood**: 場面の光（§1.5.2）。
- **髪の殻**: 顔以外の頭を覆う髪の層（§2.3）。
