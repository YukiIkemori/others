# wifi_diag — 自宅回線 / Wi-Fi 一括診断ツール

「速度測定サイトでは速いのに、実際は詰まる」の正体を数字で出すための診断スクリプトです。
Wi-Fi の電波品質から IPv6 (IPoE) の有無、経路、DNS、スループット、そして
**バッファブロート（負荷時遅延）** までを 1 コマンドで測り、JSON に保存します。

対策の前後で 2 回走らせて `--compare` すると、何がどれだけ効いたのかが表で出ます。

- 依存ライブラリなし（Python 3.9 以上の標準ライブラリのみ）
- macOS / Linux / Windows 対応
- macOS では Apple 純正の `networkQuality` があれば自動で使い、公式の RPM 値を取得します

---

## なぜスループットではなくバッファブロートを見るのか

速度測定サイトが出すのは「何も邪魔がない状態での最大速度」です。
ところが家庭で体感が悪くなる原因の多くは天井の低さではなく、**キューの詰まり**です。

回線が埋まると、途中の機器のバッファにパケットが溜まります。
帯域自体は出ているのに 1 往復に何秒もかかる状態になり、
Zoom が途切れる・ページが開かない・SSH が固まる、といった形で体感を殺します。
これがバッファブロートで、速度計には映りません。

このツールは **回線に負荷をかけながら遅延を測る** ことで、そこを可視化します。

### 指標の読み方

**RPM（Responsiveness Per Minute / 負荷時に何往復できるか）**

| RPM | 評価 | 体感 |
|---|---|---|
| 1000 以上 | A | 負荷時もほぼ無遅延 |
| 400〜999 | B | ビデオ会議も安定 |
| 200〜399 | C | 重い時に少しもたつく |
| 100〜199 | D | 同時利用でストレス |
| 100 未満 | F | 典型的なバッファブロート |

RPM 100 は 1 往復あたり約 600 ms、RPM 11 なら約 5.5 秒です。
「通信している最中は 1 クリックごとに 5 秒待つ」状態だと考えてください。

**負荷時の遅延増加（アイドル時との差）**

| 増加量 | 評価 |
|---|---|
| +30 ms 未満 | A（バッファブロートなし） |
| +30〜99 ms | B（わずか） |
| +100〜299 ms | C（はっきりある） |
| +300〜999 ms | D（重度） |
| +1000 ms 以上 | F（通信中はほぼ操作不能） |

## 使い方

```bash
# 対策前に 1 回
python3 wifi_diag.py --label before

# ルーターや契約を変えたあとに、同じ条件でもう 1 回
python3 wifi_diag.py --label after

# 差分を表で見る
python3 wifi_diag.py --compare results/2026....-before.json results/2026....-after.json
```

### オプション

| オプション | 説明 |
|---|---|
| `--label NAME` | 計測にラベルを付ける（ファイル名にも入る） |
| `--quick` | 短縮版。所要 1 分前後、通信量も半分 |
| `--no-load` | 負荷試験をしない。回線を占有できない時間帯向け |
| `--no-networkquality` | macOS の `networkQuality` を使わない |
| `--streams N` | 並列ダウンロード数（既定 4） |
| `--show FILE` | 保存済み JSON からレポートを再表示 |
| `--json` | レポートを出さず JSON だけを標準出力へ |
| `--compare A B` | 2 つの結果を比較 |

### 終了コード

重大（🚨）な所見が 1 つ以上あると終了コード `1` を返します（エラーではありません）。
スクリプトから定期実行して異常時だけ通知する、といった使い方ができます。

### ⚠️ 通信量に注意

回線を意図的に飽和させて測るため、**通信量を消費します**。
1 Gbps 級の回線だと通常モードで合計 1〜2 GB 程度になることがあります。

- 従量課金・テザリング・モバイル回線では必ず `--quick`、または `--no-load` を使ってください
- 測定中は同じ家の他の人の通信が一時的に遅くなります。ひと声かけてから実行を

## 正しく比較するためのコツ

前後の数字を比べる以上、**条件を揃えないと差が意味を持ちません**。

1. **同じ時間帯に測る。** PPPoE の混雑は夜（平日 21〜23 時）に集中します。
   昼の before と夜の after を比べると、改善を過大にも過小にも見誤ります。
   記事などで見かける「◯◯倍」の多くは、この条件が揃っていません。
2. **同じ端末・同じ場所で測る。** Wi-Fi の電波状況が変わると全部変わります。
3. **VPN を切る。** VPN 配下だと経路も遅延も別物になります。
4. **可能なら有線でも 1 回測る。** Wi-Fi 側の問題か回線側の問題かを切り分けられます。
5. **各条件で 2〜3 回測る。** 1 回の値は揺れます。

## 結果の読み方 — よくある詰まり方

### 「IPv6 が使えていません」と出た

国内の主要 ISP では、速度と遅延の改善はほぼ **IPv6 IPoE 経由** です。
古い **PPPoE** 方式だと、プロバイダの「網終端装置」という集約点を全ユーザーが通るため、
そこが混雑のボトルネックになります。IPoE はこの装置を通りません。

ISP ごとに必要なものが違います。

| ISP / 事業者 | IPoE の呼び名 | 必要なもの |
|---|---|---|
| SoftBank 光 | IPv6 高速ハイブリッド | **光BBユニットのレンタルが必須。** 認証を光BBユニットが担うため、市販ルーター単体では IPoE 化できません |
| ドコモ光 / GMO など | v6プラス, IPv6オプション ほか | 対応した市販ルーターでも可（プロバイダによる） |
| transix 系 | DS-Lite | 対応ルーターで可 |
| NURO 光 | 独自方式 | 提供機器がそのまま IPoE |

**SoftBank 光の場合の注意点:**

- 光BBユニットは単体レンタルだと月額がかかりますが、「おうち割 光セット」等の対象なら
  セット料金に含まれます。単体で払っている人は契約を見直す価値があります。
- 光BBユニット自体の無線性能は高くありません。
  **既存の市販ルーターは「アクセスポイント（ブリッジ）モード」に切り替えて電波専任にする**のが定石です。
- これを忘れてルーターモードのまま繋ぐと二重ルーターになり、NAT が二重にかかって
  別の遅延要因を作ります。このツールは経路の先頭 2 ホップがどちらもプライベート IP だった場合に
  警告を出します。

### 「二重ルーターの疑い」と出た

ISP 提供機器の下に、ルーターモードのままの市販ルーターがぶら下がっている状態です。
市販ルーター側をアクセスポイントモードに切り替えてください。

### IPv6 はあるのに RPM が低い

回線ではなく**ルーターのキュー管理**が原因の可能性があります。
OpenWrt なら SQM（`fq_codel` / `cake`）、市販機なら「スマートキュー」「Adaptive QoS」等の
名前で同等の機能がある場合があります。有効にして再測定してください。

### Wi-Fi の SNR が 20 dB を切る

電波品質側の問題です。5GHz / 6GHz 帯への変更、チャンネル変更、設置場所の見直しが効きます。
ただし**回線側が詰まっている場合、Wi-Fi をいくら調整しても RPM は上がりません**。
先に IPv6 / バッファブロートを潰してから電波を詰めてください。

## 判定の限界について

このツールが出すのは**傍証**であって、断定ではありません。

- **IPoE かどうかの判定**は、グローバル IPv6 の有無、IPv4 / IPv6 それぞれの経由 ASN、
  経路の先頭ホップから推定しています。MAP-E などの方式を直接検出しているわけではありません。
- **traceroute の 2 ホップ目に ISP 網が見える = PPPoE**、という判定は方向性としては妥当ですが、
  単独の根拠としては弱いものです。IPv6 の有無と併せて読んでください。
- **ゲートウェイが 192.168.3.x = 光BBユニット** も傍証止まりです（既定値がそうであるだけです）。
- **`--quick` や非 macOS 環境の RPM は近似値**です。Apple の `networkQuality` とは算出方法が
  異なるため、**同じツール・同じモードで測った値どうし**で比較してください。
- Windows の Wi-Fi 信号強度は OS が % しか出さないため、dBm は換算値です。
- ICMP を遮断するネットワークでは遅延が測れません。その場合はその旨が所見に出ます。
