noindex と robots.txt の違いと使い分け

公開日: 2026/11/13　SEOチェッカー 編集部

ページが検索結果に出てこない原因として多いのが、noindex と robots.txt の設定です。どちらも検索エンジンを制御する仕組みですが、役割はまったく違います。違いを理解せずに使うと、消したいページが残り、出したいページが消えることになります。

役割の違い

noindexrobots.txt の Disallow
何を止めるか検索結果への表示（インデックス）ページの取得（クロール）
書く場所各ページの HTML か HTTP ヘッダーサイト直下の robots.txt
検索結果から消えるか消える消えるとは限らない
主な用途検索に出したくないページクロールさせる必要のないページ

要点は、robots.txt は検索結果から消すための仕組みではないということです。robots.txt でブロックしたページでも、ほかのサイトからリンクされていれば、URL だけが検索結果に表示されることがあります。

noindex の書き方

HTML の head 内に書く方法が一般的です。

<meta name="robots" content="noindex">

PDF や画像など HTML 以外のファイルには、HTTP レスポンスヘッダーで指定します。

X-Robots-Tag: noindex

robots.txt の書き方

robots.txt は、サイトの一番上の階層（https://example.com/robots.txt）に置くテキストファイルです。

User-agent: *
Disallow: /admin/
Disallow: /search

Sitemap: https://example.com/sitemap.xml

この例は、すべてのクローラーに対して /admin/ 以下と /search で始まる URL の取得を禁止し、サイトマップの場所を伝えています。

両方を同時に使ってはいけない

「確実に消したいから」と、noindex を付けたページを robots.txt でもブロックするのは逆効果です。

robots.txt でブロックすると、Google はそのページを取得できません。取得できなければ、ページに書かれた noindex を読むこともできません。その結果、noindex が効かず、URL だけが検索結果に残り続けることがあります。

検索結果から消したいページは、クロールを許可したうえで noindex を付けるのが正しい手順です。

使い分けの目安

ページの種類使うもの
サンクスページ、会員限定ページ、テスト用ページnoindex
サイト内検索の結果、絞り込みで無数に生成される URLrobots.txt（クロールの無駄を減らす）
管理画面、APIrobots.txt に加えて認証をかける
内容が重複するページcanonical で正規 URL を示す

なお、robots.txt は誰でも読めるファイルです。見られて困る URL を書くと、かえって存在を知らせることになります。非公開にしたいページは認証で保護してください。

ページが検索に出ないときの確認手順

  1. ページのソースで noindex を探す。name="robots" で検索します。
  2. HTTP ヘッダーを確認する。X-Robots-Tag に noindex がないかを見ます。サーバーや CDN の設定で付いていることがあります。
  3. robots.txt を開く。対象の URL が Disallow の対象になっていないかを確認します。
  4. canonical を確認する。別の URL を指していると、そのページ自体は検索結果に出ません。
  5. Google Search Console の URL 検査で確認する。Google が実際にどう認識しているかが分かります。

SEOチェッカーでは、1から4をまとめて確認できます。noindex や robots.txt のブロックが見つかった場合は、最優先の改善点として表示します。

よくある事故

  • 公開時に noindex を外し忘れる。開発中のサイトに付けた設定が本番に残る例です。WordPress の「検索エンジンがサイトをインデックスしないようにする」のチェックも同じ働きをします。
  • robots.txt に Disallow: / が残っている。サイト全体がクロールされなくなります。
  • CSS や JavaScript をブロックしている。Google がページを正しく描画できず、評価が下がる原因になります。
