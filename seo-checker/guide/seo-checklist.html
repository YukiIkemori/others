SEOチェックリスト：公開前に確認したい70項目

公開日: 2026/11/13　SEOチェッカー 編集部

SEO の内部対策は項目が多く、どこまで確認すれば十分なのか分かりにくいものです。このページでは、SEOチェッカーが実際に採点している約70項目を7つの分野に分けて一覧にしました。上から順に確認すれば、検索エンジンに正しく読まれ、検索結果で選ばれやすいページの土台が整います。

最初に確認する「致命的な3項目」

次の3つは、1つでも当てはまるとページが検索結果に出なくなります。他の項目より先に確認してください。

  • noindex が付いていないか。meta robots タグと、HTTP ヘッダーの X-Robots-Tag の両方を確認します。
  • robots.txt でクロールを禁止していないか。開発中に書いた Disallow: / が残っている例がよくあります。
  • ページが HTTP 200 を返しているか。404 や 500 を返すページはインデックスされません。

SEOチェッカーでは、この3項目のどれかに問題があると総合点を45点までに制限しています。ほかがどれだけ整っていても、検索に出ないページは評価のしようがないからです。詳しくは「noindex と robots.txt の違い」で解説しています。

1. 基本メタ情報（9項目）

  • タイトルタグがあり、内容を表す固有の文言になっている
  • タイトルの長さが全角15〜32文字程度に収まっている
  • タイトルタグが1ページに1つだけである
  • メタディスクリプションがあり、全角70〜120文字程度で要点をまとめている
  • メタディスクリプションがタイトルの繰り返しになっていない
  • viewport が設定され、スマートフォンで正しく表示される
  • html 要素に lang 属性がある
  • 文字コード（meta charset）が宣言されている
  • canonical が1つだけあり、自分自身の絶対 URL を指している

書き方の詳細は「タイトルタグの文字数と書き方」「メタディスクリプションの書き方」を参照してください。

2. コンテンツ（8項目）

  • H1 が1つあり、ページの主題を表している
  • 見出しが h1 → h2 → h3 の順で、階層を飛ばしていない
  • 空の見出しがない
  • 検索意図を満たすだけの本文量がある
  • 本文が初期 HTML に含まれている（JavaScript の実行を前提にしていない）
  • 本文の主題とタイトルの語句が一致している
  • 運営者情報・問い合わせ先・プライバシーポリシーへの導線がある
  • 公開日・更新日が分かる

3. クロール・インデックス（12項目）

  • noindex が指定されていない
  • meta robots に不要な nofollow がない
  • robots.txt があり、対象ページのクロールを許可している
  • robots.txt に Sitemap の場所が書かれている
  • XML サイトマップがあり、XML として正しい
  • 対象ページがサイトマップに載っている
  • HTTP ステータスが 200 である
  • リダイレクトが連鎖していない（1回以内）
  • 恒久的な移転に 302 ではなく 301 を使っている
  • URL が短く、小文字・ハイフン区切りで整理されている
  • meta refresh によるリダイレクトを使っていない
  • 多言語サイトの場合、hreflang が相互に設定されている

4. リンク・画像（11項目）

  • リンク切れ（404 など）がない
  • 内部リンクがリダイレクトを経由していない
  • 関連ページへの内部リンクがある
  • リンクテキストのないリンクがない
  • 「こちら」「詳細」だけのリンクテキストを避けている
  • href が空・「#」・javascript: のリンクがない
  • 画像に alt 属性がある
  • 画像に width と height が指定されている
  • ファーストビュー外の画像を遅延読み込みしている
  • WebP や AVIF などの軽い画像形式を使っている
  • リンクの数が多すぎない

リンク切れの探し方は「リンク切れの調べ方と直し方」にまとめています。

5. SNS・構造化データ（7項目）

  • og:title・og:description・og:image・og:url が揃っている
  • og:image が https から始まる絶対 URL である
  • twitter:card が設定されている
  • ページの種類に合った構造化データ（JSON-LD）がある
  • JSON-LD に構文エラーがない
  • 各スキーマの必須プロパティが揃っている
  • 下層ページにパンくずリストの構造化データがある

構造化データの始め方は「構造化データ（JSON-LD）の基本」を参照してください。

6. 技術・セキュリティ（14項目）

  • HTTPS で配信されている
  • HTTPS ページ内で http:// のリソースを読み込んでいない
  • DOCTYPE 宣言がある
  • HTML のサイズが大きすぎない
  • DOM の要素数が多すぎない（目安は1,500以下）
  • head 内の外部スクリプトに async か defer が付いている
  • CSS ファイルを読み込みすぎていない
  • font や center などの廃止されたタグを使っていない
  • ピンチズームを禁止していない
  • HSTS（Strict-Transport-Security）を返している
  • X-Content-Type-Options: nosniff を返している
  • クリックジャッキング対策（X-Frame-Options など）がある
  • HTTP/2 以上で配信されている
  • DNS が正しく解決でき、IPv6 に対応している

7. 表示速度（11項目）

  • LCP（最大コンテンツの表示）が 2.5 秒以内
  • INP（操作への応答）が 200 ミリ秒以内
  • CLS（レイアウトのずれ）が 0.1 以下
  • TBT（操作をブロックした時間）が 200 ミリ秒以内
  • FCP（最初の描画）が 1.8 秒以内
  • Speed Index が 3.4 秒以内
  • Lighthouse のパフォーマンススコアが 90 以上
  • Lighthouse の SEO スコアが 90 以上
  • アクセシビリティスコアが 90 以上
  • ベストプラクティススコアが 90 以上
  • ページ全体の転送量が 1.6MB 以下

各指標の意味と改善方法は「Core Web Vitals の基準と改善方法」で解説しています。

サイト全体で確認する項目

1ページずつでは見つからない問題もあります。サイト全体では次の点を確認します。

  • タイトル・メタディスクリプション・H1 がページ間で重複していない
  • エラーを返すページがない
  • 内部リンク切れがない
  • サイトマップに、noindex やリダイレクトされる URL が載っていない
  • インデックスさせたいページがサイトマップから漏れていない
  • 内容の薄いページが多くない
  • どこからもリンクされていないページがない

優先順位の付け方

すべてを一度に直す必要はありません。次の順番で進めると、少ない作業で効果が出やすくなります。

  1. 検索に出なくなる問題を直す。noindex、robots.txt のブロック、エラーページです。
  2. 全ページに共通する問題を直す。テンプレートを1か所直せば全ページに反映されるので、費用対効果が最も高くなります。
  3. 検索結果での見え方を整える。タイトルとメタディスクリプションはクリック率に直結します。
  4. 表示速度を改善する。実ユーザーのデータで「不良」と判定されている指標から着手します。

なお、このチェックリストは技術的な土台を整えるためのものです。検索順位を最終的に決めるのは、検索した人の疑問に答える内容になっているかどうかです。土台を整えたうえで、内容の充実に時間を使ってください。
