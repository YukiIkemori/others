構造化データ（JSON-LD）の基本と書き方

公開日: 2026/11/13　SEOチェッカー 編集部

構造化データとは、「このページは記事で、著者は誰で、公開日はいつか」といった情報を、検索エンジンが確実に読み取れる形式で書いたものです。設定すると、検索結果にパンくずや評価の星などが表示される「リッチリザルト」の対象になります。

構造化データで得られる効果

  • 検索結果の表示が豊かになる。パンくずリスト、レビューの星、商品の価格、イベントの日時などが表示され、目に留まりやすくなります。
  • 内容が正確に伝わる。ページの種類や、運営者・著者・公開日などの情報を、検索エンジンが推測ではなく明示された情報として読み取れます。

構造化データを入れただけで検索順位が上がるわけではありません。また、設定してもリッチリザルトが必ず表示されるとは限らず、表示するかどうかは Google が判断します。

JSON-LD の書き方

構造化データにはいくつかの書式がありますが、Google が推奨しているのは JSON-LD です。HTML の中に script タグで書くため、ページの見た目に影響しません。

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "株式会社サンプル",
  "url": "https://example.com/",
  "logo": "https://example.com/logo.png"
}
</script>

@type が情報の種類（スキーマ）で、その下に種類ごとに決められた項目を書きます。head 内でも body 内でも構いません。

よく使うスキーマ

スキーマ使うページ主な必須・推奨項目
BreadcrumbList下層ページ全般itemListElement（各階層の名前と URL）
Article / BlogPosting記事、ブログheadline、image、datePublished、author
Product商品ページname と、offers・review・aggregateRating のいずれか
Organizationトップページ、会社概要name、url、logo
LocalBusiness店舗、医院name、address、営業時間、電話番号
WebSiteトップページname、url
Eventイベント告知name、startDate、location
JobPosting求人title、description、datePosted、hiringOrganization

最初に入れるなら、ほぼすべてのサイトで使える BreadcrumbList と、トップページの Organization・WebSite がおすすめです。

パンくずリストの例

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "ホーム", "item": "https://example.com/" },
    { "@type": "ListItem", "position": 2, "name": "ブログ", "item": "https://example.com/blog/" },
    { "@type": "ListItem", "position": 3, "name": "記事のタイトル" }
  ]
}
</script>

設定すると、検索結果の URL 表示が「example.com › ブログ」のような階層の表示になります。

FAQ と HowTo の現状

以前は FAQPage を設定すると、検索結果に質問と回答が展開して表示されました。現在この表示は、政府機関や医療機関など一部の権威あるサイトに限定されています。HowTo のリッチリザルトも廃止されました。これらを設定しても害はありませんが、検索結果の見た目が変わることは期待できません。

よくあるエラー

  • JSON の構文エラー。末尾の余分なカンマ、引用符の閉じ忘れ、全角の引用符が原因の大半です。1か所でも誤りがあると、そのブロック全体が読み取られません。
  • 必須項目の不足。Article に image や datePublished がない、Product に価格や評価がない、といった例です。
  • ページに表示されていない内容を書く。画面にない評価や価格を構造化データだけに書くことは、Google のガイドライン違反です。
  • テンプレートの変数が展開されていない。出力された HTML を必ず確認します。

確認方法

  1. SEOチェッカーで確認する。JSON-LD の構文エラーと、主要なスキーマの必須項目の不足を検出します。検出されたスキーマの種類も一覧で表示します。
  2. Google のリッチリザルト テストで確認する。Google がリッチリザルトの対象として認識できるかを判定します。
  3. Search Console の拡張レポートで確認する。公開後に、サイト全体でエラーが出ていないかを継続して確認できます。
