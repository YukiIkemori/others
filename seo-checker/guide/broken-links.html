リンク切れの調べ方と直し方

公開日: 2026/11/13　SEOチェッカー 編集部

リンク切れとは、リンクをクリックしても「ページが見つかりません（404）」と表示される状態のことです。サイトを長く運営していると必ず発生します。このページでは、リンク切れが SEO に与える影響と、調べ方・直し方を解説します。

リンク切れが SEO に与える影響

Google は、404 のページがあること自体はサイトの評価を下げる理由にならないと説明しています。存在しないページが 404 を返すのは正常な動作だからです。問題になるのは、自分のサイト内にリンク切れを放置している場合です。

  • 訪問者が離脱する。読みたかったページにたどり着けず、サイトへの信頼も下がります。
  • 評価が受け渡されない。内部リンクは、ページの評価を別のページに伝える経路です。リンク先が存在しなければ、そこで途切れます。
  • クロールの無駄になる。クローラーが存在しないページの取得に時間を使うことになります。
  • 削除したページへの被リンクが無駄になる。外部サイトからリンクされていたページを消すと、その評価を失います。

リンク切れが起きる原因

  • ページを削除した、または URL を変更した
  • リンクの URL を書き間違えた
  • サイトのリニューアルでディレクトリ構成が変わった
  • リンク先の外部サイトがページを削除した、またはサイトを閉鎖した
  • 相対パスの指定を誤り、意図しない URL になっている

最後の例は気づきにくいので注意が必要です。たとえば /docs/security/ のページに docs/pages/team.md という相対リンクがあると、リンク先は /docs/security/docs/pages/team.md になり、404 になります。

リンク切れの調べ方

1ページだけ調べる

SEOチェッカーの1ページ診断では、ページ内のリンクを最大60本まで実際に開いて、リンク切れを検出します。切れているリンクの URL とリンクテキストが一覧で表示されるので、該当箇所をすぐに見つけられます。

サイト全体を調べる

サイト全体診断では、最大50ページを巡回して内部リンクを確認します。切れているリンク先と、そのリンクを張っているページが分かります。

Google Search Console で調べる

Search Console の「ページ」レポートで、「見つかりませんでした（404）」に分類された URL を確認できます。Google が実際に取得しようとした URL なので、外部サイトからリンクされている削除済みページを見つけるのに向いています。

ステータスコードの見方

コード意味対応
200正常対応不要
301 / 308恒久的な転送内部リンクなら、転送先の URL に書き換える
302 / 307一時的な転送恒久的な移転なら 301 に変更する
404 / 410ページが存在しないリンクを直すか、転送を設定する
500 番台サーバーエラーサーバー側の不具合を調べる
403 / 429アクセス拒否・回数制限自動アクセスが拒否されただけの場合がある。ブラウザで開いて確認する

SNS など一部のサイトは、ツールからの自動アクセスを拒否します。この場合はリンク切れとは限らないため、SEOチェッカーでは「判定不能」として、リンク切れには数えていません。

リンク切れの直し方

内部リンクの場合

  1. リンク先の URL が間違っているなら、正しい URL に書き換える。
  2. ページを移動したなら、新しい URL に書き換える。あわせて、古い URL から新しい URL へ 301 リダイレクトを設定します。
  3. ページを削除したなら、リンクを外す。内容の近いページがあれば、そちらにリンクを張り替えます。

外部リンクの場合

リンク先のサイトが移転していれば、新しい URL に書き換えます。ページがなくなっていれば、同じ内容を扱う別の信頼できるページにリンクを張り替えるか、リンクを削除します。

削除したページには 301 リダイレクトを設定する

ほかのサイトからリンクされていたページや、検索から訪問があったページを削除・移動するときは、内容の近いページへ 301 リダイレクトを設定します。訪問者を迷わせず、ページが得ていた評価も引き継げます。

注意点は、関係のないページへ転送しないことです。削除したすべてのページをトップページに転送すると、Google は「ページが存在しない」のと同じ扱いをすることがあります。内容が対応するページがない場合は、404 のままにしておくのが適切です。

リダイレクトを経由する内部リンクも直す

リンク切れではありませんが、内部リンクが転送を経由している状態も改善の対象です。http から https へ、末尾のスラッシュの有無などで、クリックのたびに余計な転送が発生します。リンクの href を転送後の最終 URL に書き換えると、表示が速くなり、クロールの無駄も減ります。
