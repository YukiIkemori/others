# お問い合わせフォームの設置

`/reserve/` のフォームは、同じ階層の `send.php` が受け取ってメールを送ります。
PHP の標準機能だけで動きます。ライブラリも外部サービスも使いません。

## 動くところ・動かないところ

| 置き場所 | 送信 |
|---|---|
| さくらのレンタルサーバ（本番） | **動く** |
| Firebase の確認用サイト | **動かない**（PHPが無い。押すと「確認用サイトでは送信されません」と出る） |

## 公開前にやること

### 1. 差出人のアドレスを作る

`send.php` の先頭、`FROM_ADDR` を直します。**ここだけは必ず直してください。**

```php
const FROM_ADDR  = 'no-reply@shiomihouse.com';   // ← 実在するアドレスに
```

shiomihouse.com のサーバーから送るので、差出人も **shiomihouse.com のアドレス**
である必要があります。`@gmail.com` のアドレスを差出人にすると、
Gmail 側で「なりすまし」と判断され、迷惑メール行きか、そもそも届きません。

さくらのコントロールパネル →「メール」→「メールアドレスの追加」で
`no-reply@shiomihouse.com` を1つ作り、そのアドレスをここに書きます。
（受信はしないアドレスなので、パスワードは控えるだけで結構です）

### 2. 受け取り先を確認する

```php
const TO_ADDR    = 'shiomihouse@gmail.com';
```

ここに届きます。変えたいときはこの行を直します。
届いたメールに **そのまま返信すると、お客様に届く** ようにしてあります
（Reply-To にお客様のアドレスが入っています）。

### 3. 置く

`site/` の中身をそのままドキュメントルートに上げれば、
`send.php` も一緒に上がります。パーミッションは既定のままで結構です。

`send.php` の隣に、連投よけの記録用に `shiomi-form-log/` という
フォルダが自動でできます（公開ディレクトリの外に作られます）。
消しても差し支えありません。

### 4. 自分宛に1通送って確かめる

公開したら、実際にフォームから1通送ってみてください。

- 宿に「【汐見の家】ご予約・お問い合わせ（お名前様）」が届く
- 送った人に「【汐見の家】お問い合わせを受け付けました」が届く
- 送信後に `/reserve/done/` が表示される

届かないときは、まず迷惑メールの箱を見てください。
それでも無ければ、たいてい 1. の差出人アドレスが原因です。

## 迷惑メール対策として入れてあるもの

- **見えない入力欄**（人には見えない欄。機械が埋めると受け付けず、
  相手には成功したように見せる。何度も試させないため）
- **連投よけ**（同じ相手から1時間に5件まで）
- **本文のURL数**（3つ以上入っていたら広告とみなす）
- **メールヘッダへの改行の混入を防ぐ**（第三者へのBcc送信を仕込まれないように）

CAPTCHA は入れていません。島の小さな宿に来る量なら、上の4つで足ります。
もし迷惑メールが増えるようなら、そのときに足します。

## 項目を増やしたいとき

`make-reserve.py` の `FIELDS` と `FORM` の両方に足して、

```
python3 make-reserve.py
python3 add-structured-data.py
python3 add-head-meta.py
python3 verify.py
```

を流してください。画面とメール本文の両方が同時に更新されます。
（片方だけ直して食い違う、という事故を避けるためにこうしてあります）
