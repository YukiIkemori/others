# このサイトを預かるAIへ

古民家ゲストハウス「汐見の家」（愛媛県上島町佐島）のウェブサイトです。
2026年9月に、WordPressから静的HTMLへ作り直しました。
この文書は、これから文言や写真の手直しをするあなたへの申し送りです。

**お願いする相手は、ウェブに詳しくない方です。**
「ここを直せば直ります」と、ファイル名と該当の文を示して案内してください。

この文書は2部構成です。

- **0章** … サイトをサーバーに載せるまでの手順。まだ載っていないならここから
- **1章以降** … 載ったあとに、文言や写真を直すときの決めごと

---

## 0. サーバーに置くまで（最初にこれをやります）

この章は、**まだサイトがサーバーに載っていない段階**のための手順です。
すでに載っているなら、1章へ進んでください。

お願いする相手はウェブに詳しくない方です。**1ステップずつ、
「いま何をしているか」を添えて**案内してください。
つまずきやすい箇所には ⚠ を付けてあります。

### 0-1. 受け取ったファイルを開く

サイト一式はZIPで届きます。**1つのファイル**で届いた場合は、
普通に右クリック →「すべて展開」で開けます。0-2 へ進んでください。

**4つに分かれて届いた場合**は、少し手間が要ります。

```
shiomihouse-full.z01
shiomihouse-full.z02
shiomihouse-full.z03
shiomihouse-full.zip
```

⚠ **Windows標準の「展開」では開けません。** 7-Zip（無料）などの
解凍ソフトが必要です。

1. 4つのファイルを **同じフォルダに全部** 置く
   （1つでも欠けていると解凍できません）
2. 7-Zip をインストールする（https://7-zip.opensource.jp/）
3. **`shiomihouse-full.zip`（拡張子が .zip のもの）を右クリック**
   →「7-Zip」→「ここに展開」
   ※ .z01 の方ではありません。.zip の方です
4. 「汐見の家サイト一式」というフォルダができます

Macの場合は、標準の解凍では失敗することがあります。
The Unarchiver（無料）を使ってください。

中身はこうなっています。

```
汐見の家サイト一式/
  アップロードするもの/    ← サーバーに上げるのはこの中身
  説明書/                  ← サーバーには上げません
```

### 0-2. さくらのサーバーに、作業用のアドレスを作る

いきなり本番のアドレス（shiomihouse.com）には上げません。
**作業用のサブドメイン**を作って、そこでじっくり直していただきます。

⚠ **サブフォルダ（shiomihouse.com/test/ のような形）ではダメです。**
ページ同士のつながりが2,021箇所、旧アドレスからの転送が110本、
すべて壊れます。必ずサブドメインにしてください。

**手順**

1. さくらのレンタルサーバ コントロールパネルにログイン
   （https://secure.sakura.ad.jp/rs/cp/）
2. 左メニューの「ドメイン/SSL」→「ドメイン/SSL」
3. 「ドメイン新規追加」ボタン
4. 「他社で取得したドメインを使う」ではなく、
   **すでに登録済みの shiomihouse.com の行にある「設定」** から
   サブドメインを追加します
   （画面の作りはコントロールパネルの版によって変わります。
     迷ったら「サブドメイン 追加」でさくらのヘルプを検索してください）
5. サブドメイン名に `test` と入れる → `test.shiomihouse.com` になります
6. **公開フォルダに `test` を指定**します
   （`/home/アカウント名/www/test/` が作られます）
7. 保存

⚠ **DNSがさくら以外で管理されている場合**、サブドメインを追加しても
繋がりません。ドメインを管理している会社（お名前.com、ムームードメインなど）
の管理画面で、`test` のレコードを追加する必要があります。
分からなければ、さくらのサポートに
「shiomihouse.com のサブドメインを追加したい。DNSは他社管理です」
と問い合わせれば案内があります。

### 0-3. 無料SSLを有効にする

同じ「ドメイン/SSL」の画面で、`test.shiomihouse.com` の
**SSL証明書を「無料SSL（Let's Encrypt）」で発行**します。

⚠ 有効になるまで数十分かかることがあります。急がず待ってください。

### 0-4. FTPの接続情報を調べる

コントロールパネルの「サーバー情報」→「サーバー情報の表示」あたりに
書いてあります。

| 項目 | 例 |
|---|---|
| FTPサーバ名（ホスト） | `アカウント名.sakura.ne.jp` |
| FTPアカウント（ユーザー名） | `アカウント名` |
| FTPパスワード | サーバーのパスワード |
| 接続方法 | **FTPS（明示的）** を選んでください |

⚠ このパスワードは、**メールやチャットに貼らないでください。**

### 0-5. FileZilla でアップロードする

1. FileZilla をインストールする（https://filezilla-project.org/ の
   **FileZilla Client** の方。Server ではありません）
2. 「ファイル」→「サイトマネージャー」→「新しいサイト」
3. 上の表の情報を入れる。暗号化は
   「明示的なFTP over TLSが利用可能なら使用する」
4. 「接続」
5. 右側（サーバー側）で `/home/アカウント名/www/test/` を開く
   ※ `www` の下に `test` フォルダができているはずです
6. 左側（自分のパソコン）で
   `汐見の家サイト一式/アップロードするもの/` を開く
7. **その中身を全部選んで**（フォルダごとではなく、中身を）
   右側にドラッグ

⚠ **700ファイル以上、64MBあります。20〜40分かかります。**
途中で止めないでください。終わったら、FileZillaの下側のログに
「失敗した転送」が0件であることを確認してください。
失敗があれば、その行を右クリックして再転送できます。

### 0-6. .htaccess にリネームする

アップロードした中に `htaccess-test.txt` があります。
これを **サーバー側で** `.htaccess` にリネームします。

1. FileZillaの右側（サーバー側）で `htaccess-test.txt` を右クリック
2. 「ファイル名の変更」
3. `.htaccess` と入力（**先頭にドット**が付きます）

⚠ 自分のパソコン側でリネームしようとすると、Windowsでは
「ファイル名を入力してください」と怒られます。**サーバー側でやってください。**

⚠ リネーム後、FileZillaの画面から消えたように見えることがあります。
ドットで始まるファイルは隠しファイル扱いのためです。
「サーバー」メニュー →「隠しファイルの強制表示」で見えます。

`htaccess-honban.txt` はそのまま置いておいてください。
本番に切り替えるときに使います。

### 0-7. 表示を確認する

ブラウザで `https://test.shiomihouse.com/` を開きます。

**確認するところ**

- [ ] トップページが表示される（夜の古民家の写真が出る）
- [ ] メニューから各ページに移動できる
- [ ] スマホの幅で見て、横にはみ出していない
- [ ] 「読み物」の中のページで写真が出ている
      （例: `/stories/renovation/ido/`）
- [ ] 旧アドレスが転送される
      `https://test.shiomihouse.com/1331/` → 井戸のリノベーション
      `https://test.shiomihouse.com/166/` → ロバート汐見の足跡

### 0-8. 問い合わせフォームを動かす

このままでは**メールが届きません。** 1か所だけ設定が要ります。

1. コントロールパネルの「メール」→「メールアドレスの一覧」→
   「新規追加」で、shiomihouse.com のアドレスを1つ作る
   （受信はしないので `no-reply` などで結構です）
2. `reserve/send.php` をテキストエディタで開く
3. 次の行を、いま作ったアドレスに書き換える

```php
const FROM_ADDR  = 'no-reply@shiomihouse.com';
```

4. 保存して、そのファイルだけ上げ直す
5. フォームから自分宛に1通送ってみる

⚠ **`@gmail.com` のアドレスを差出人にしてはいけません。**
shiomihouse.com のサーバーから送るので、なりすまし扱いされて
届きません。必ず shiomihouse.com のアドレスにしてください。

詳しくは `問い合わせフォームの設置.md` にあります。

### 0-9. よくあるつまずき

| 症状 | 原因と直し方 |
|---|---|
| ページは出るが、見た目が崩れて文字だけ並ぶ | `style.css` が上がっていない。ファイル1つだけ上げ直す |
| 画像が1枚も出ない | `img` フォルダごと上げられていない。フォルダ構造を確認 |
| 一部のページだけ画像が出ない | そのページのフォルダ階層がずれている。`stories/renovation/ido/` のような深い階層を確認 |
| 旧アドレスが転送されない | `.htaccess` のリネームができていない。隠しファイルを表示して確認 |
| 文字化けする | ファイルを編集したときに文字コードが変わった。**UTF-8** で保存し直す |
| フォームを押すと真っ白／エラー | `send.php` の書き換えでPHPの文法を壊した可能性。バックアップから戻す |
| フォームは送れるがメールが来ない | `FROM_ADDR` が `@gmail.com` のまま。0-8 を見直す |
| 直したのに反映されない | ブラウザの再読み込み（Ctrl+Shift+R / Cmd+Shift+R）。それでも直らなければ、上げたファイルの場所が違う |

### 0-10. 本番に切り替えるとき

作業が終わってからです。**この作業は制作した者に声をかけてから**
やっていただくのが安全です。

1. 本番の shiomihouse.com に独自SSLを有効にする
2. `アップロードするもの` の中身を、本番のフォルダ
   （`/home/アカウント名/www/`）に上げる
3. **`htaccess-honban.txt` を `.htaccess` にリネーム**して設置
   （テスト用と入れ替える。テスト用には検索よけが入っているため、
     そのままだと本番が検索結果に出ません）
4. 旧アドレスの転送をいくつか踏んで確かめる
5. `.htaccess` を開いて【HTTPS】の2行のコメント（`#`）を外す
   ⚠ SSLが有効になる前に外すと、サイトに繋がらなくなります
6. フォームから1通送って、届くか確かめる
7. Googleサーチコンソールで `sitemap.xml` を送信する
8. **ここまで確認できてから** WordPress（`/wp/`）を消す

⚠ 8 の前に、`/wp/wp-content/uploads/` を手元に落としておいてください。
消すと、元の写真が二度と取れなくなります。

## 1. 文言を直すときに、いちばん大事なこと

### HTMLが正本です

このサイトは、もともとPythonの生成スクリプトから書き出しました。
**そのスクリプトは同梱していません。** 手直しが全部消える事故を防ぐためです。

いま手元にあるHTMLファイルが唯一の正本です。文言を直すときは、
**HTMLファイルを直接開いて、文字のところだけ書き換えてください。**

### 守っていただきたい決めごと

このサイトは、次の方針で作られています。崩さないでください。

| 決めごと | 理由 |
|---|---|
| **JavaScriptを使わない** | 1行も入っていません。動きはすべてCSSで作っています。追加すると、この設計の一貫性が崩れます |
| **外部から何も読み込まない** | ウェブフォント、CDN、アイコンライブラリ、アクセス解析、いずれも使っていません。表示が外部サービスの都合に左右されず、個人情報も外に出ません |
| **CSSは `style.css` の1枚だけ** | 45ページすべてがこれ1枚を見ています。ここを直すと全ページに影響します |
| **ページ間のリンクは `/about/` のようにルートから書く** | ドメインの直下に置く前提です。サブフォルダに移すと全部壊れます（後述） |
| **画像とCSSは `../img/` のように相対で書く** | 階層の深さに応じて `../` の数が変わります。ここを間違えると画像が出なくなります |

### 触ってはいけないもの

- `style.css` の構造（色や余白の変数）— 見た目の決めごとは `見た目の決めごと.md` にあります
- `<head>` の中の `<script type="application/ld+json">` — 検索エンジン向けの情報です。料金や定員を直したら、ここも合わせてください（`index.html` にあります）
- `.htaccess` — 旧サイトのURLから新URLへの転送が108本入っています。消すと、これまで検索やSNSから来ていた人が迷子になります
- `sitemap.xml` `robots.txt` — 検索エンジン向け

## 3. 文言を直すとき

### 手順

1. `文言の置き場所.md` で、直したい文があるファイルを探す
2. そのHTMLをテキストエディタで開く
3. `<` と `>` で囲まれた部分は触らず、**文字のところだけ**書き換える
4. **UTF-8** で保存する（文字コードを変えないこと）
5. FTPでそのファイルだけ上げ直す
6. ブラウザで見て確かめる

### 全ページに入っている文言

宿の名前、住所、電話番号、フッターの文、メニューの並びなどは
**45ファイルすべてに同じ文が入っています。**
1か所だけ直すと食い違うので、フォルダ内を一括置換してください。
どれが該当するかは `文言の置き場所.md` の最後にまとめてあります。

### 料金や定員を直すとき

次の場所に散らばっています。**全部揃えてください。**

- `index.html` — 「宿のあらまし」の表、および `<head>` の構造化データ
- `about/index.html` — 「料金」の表
- `reserve/index.html` — 「料金」の表、フォームの選択肢の説明
- `faq/index.html` — 「料金はいくらですか。」の答え、および `<head>` の構造化データ
- `school/index.html` — 本文
- 各ページの `<head>` の `<meta name="description">` と `<meta property="og:description">`

### 見出しやタイトルを直すとき

`<title>` を直したら、同じページの `<meta property="og:title">` も
同じ文言に揃えてください。SNSに貼られたときの見出しです。
`<meta name="description">` と `<meta property="og:description">` も同様です。

## 4. 写真を差し替えるとき

写真は1枚につき4つの大きさを用意しています。

```
img/goemon-bath-480.jpg   スマホ用
img/goemon-bath-800.jpg
img/goemon-bath-1200.jpg
img/goemon-bath-1800.jpg  PC用
```

HTMLではこう書かれています。

```html
<img src="../img/goemon-bath-1800.jpg"
     srcset="../img/goemon-bath-480.jpg 480w, ... 1800w"
     sizes="..." alt="五右衛門風呂" width="1800" height="1200" loading="lazy">
```

差し替えるときは、**同じ名前で4つの大きさを作って上書き**してください。
1枚だけ差し替えると、画面の大きさによって古い写真が出ます。

- `width` と `height` は、1800px版の実際の縦横を入れてください。
  ここが実物と違うと、読み込み中にページがガタつきます
- `alt` は写真の説明です。目の見えない方が読み上げで聞く文です。必ず書いてください
- `loading="lazy"` は残してください（最初の1枚だけ付いていません。それでよいです）

## 5. 直したあとの確認

**必ずこの5つを見てください。**

1. **スマホの幅（390pxくらい）で横にはみ出していないか**
   ブラウザの開発者ツールで幅を390pxにして、横スクロールバーが出なければOK
2. **リンクが切れていないか**
   直したページのリンクをひととおり押してみる
3. **写真が出ているか**
   特に階層の深いページ（`stories/renovation/ido/` など）。`../` の数を間違えやすい
4. **文字化けしていないか**
   保存の文字コードがUTF-8になっているか
5. **問い合わせフォームが動くか**（フォーム周りを触ったとき）
   自分宛に1通送ってみる

## 6. 問い合わせフォームについて

`reserve/send.php` がメールを送ります。PHPの標準機能だけで動きます。

**公開前に必ず、`FROM_ADDR` を実在するアドレスに変えてください。**
詳しくは `問い合わせフォームの設置.md` を読んでください。

迷惑メール対策として、見えない入力欄・連投よけ・本文のURL数・
メールヘッダへの改行混入よけを入れてあります。外さないでください。

## 7. やってはいけないこと

| してはいけないこと | 何が起きるか |
|---|---|
| サブフォルダ（`/test/` など）に移す | ページ間のリンク2,021箇所とリダイレクト110本が全部壊れます。**必ずドメインまたはサブドメインの直下に置いてください** |
| `.htaccess` を消す・書き換える | 旧サイトのURLからの転送が止まり、検索やSNSから来た人が404になります |
| JavaScriptを足す | この設計の一貫性が崩れます。動きが必要なら、まずCSSでできないか考えてください |
| ウェブフォントやCDNを足す | 表示が外部サービス任せになります |
| 画像を1つの大きさだけ差し替える | 画面の大きさによって古い写真が出ます |
| `style.css` を大きく書き換える | 45ページ全部に影響します。触る前に `見た目の決めごと.md` を読んでください |
| 文字コードをShift_JISで保存する | 全部文字化けします |

## 9. 元のサイトとの照合について

このサイトの文言は、旧サイト152ページを引き直して突き合わせてあります。
読み物42本は元記事の本文をそのまま載せています（書き換えていません）。

固定ページの文章は書き起こしたものですが、
**元サイトに根拠のない記述は落としてあります。**
新しく事実を書き足すときは、必ず宿の方に確認してください。
「たぶんこうだろう」で書かないでください。実際、それで一度やり直しました。

照合の記録は `文言の確認事項.md` にあります。
