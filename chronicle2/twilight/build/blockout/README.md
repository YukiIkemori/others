# 骨組み先行方式（3D blockout first, painted after）

当たり判定と「物の前後関係」を絵から推定するのをやめて、先に作った簡単な3Dの骨組みからそのまま取り出す方式の試作です。
絵は、骨組みを描画した画像を画像モデルに渡して「形は動かさず、この画風で塗り直す」ことで作ります。

遊べる版のデータは `../../site3d/`（`game.js` などは `../site/` への symlink）。

## 手順

作業フォルダに 3D 側の出力（`site/px/map.json, geo.png, walk.png`。`chronicle2/monastery` の bake 出力）を置いて実行します。

1. `conv.py out` … 3D データをエンジン形式に変換（`out/walk.png, h.npy, height.png, info.json`）。絵は一切見ません。
2. 塗り: `python3 ../img.py prompts/paint.txt gen/out_1x.png --size 1920x2048 --quality high --image guide_1x.png --image styleref.png`
   - `guide_1x.png` = 骨組みの描画（空はマゼンタ）、`styleref.png` = 仕上がりの見本（気に入っているマップの切り抜き）。
3. `match.py guide_1x.png gen/out_1x.png pts.npy` … 骨組みと塗った絵のずれを窓ごとに測る。
4. `warp.py pts.npy out map_base.json stage` … 3D 側のデータを絵に合わせて動かす（絵は動かさない）。光や出入口の座標も同じ変換を通す。
5. 確認用マスク: `python3 ../img.py prompts/mask_raised.txt gen/m_raised.png --size 1920x2048 --image gen/out_1x.png`、
   `match.py st_paint.png gen/m_raised.png pts_mask.npy`、`check.py stage gen/out_1x.png gen/m_raised.png pts_mask.npy report.jpg`
   … 歩き回る代わりの自動チェック。絵に描かれなかった低い小物を外し、食い違いを色分けした全体図を出します。

## 2026-11-10 の試作でわかったこと

- 画像モデルは配置を守るが、絵全体をわずかに拡大する（今回は横 +0.7 %、縦 +1.9 %。端では 20〜40 px のずれ）。
  そのまま重ねると当たり判定がずれるので、手順 3〜4 が必須。補正後の残りのずれは平均 1.3〜1.5 px（95 % が 3.7 px 以内）。
- 3D にある立体物の 92 % は絵にも描かれていた。描かれなかったのは低い茂み 7 個だけで、自動で外した。
- 補正後、ランダム歩行 400 回で引っかかり 0。
- `gpt-image-2` の制限: 両辺 16 の倍数、長辺 3840 以下、総画素は約 829 万まで。`input_fidelity` は使えない。
- 未対応: 段差のある地形では、物の前後を「画面上の高さ」だけで決める今のエンジン形式（height.png）では足りず、奥行きそのものを持たせる必要がある。

## 崖と雲海の版（2026-11-11、段差のある地形）

平らな旧マップでは方式の良さが分かりにくかったので、気に入られている「崖の上の修道院」の構図を骨組みから作り直した版です。
遊べるデータは `../../site_cliff/`。

- `vox.py` … 箱・円柱・円すい・アーチ・階段などを積んで地形を作る小さな道具と、エンジン用データを焼く `bake()`。Blender は使いません。
  見た目用の下絵（`guide.png`）、当たり判定（`walk.png`）、前後関係（`height.png`）、足元の高さ（`floor.png`）が同じ立体から出ます。
- `cliff_world.py out` … 3 段の台地、階段 5 本、門、屋根のない身廊、鐘楼、見晴らし台、池、楓、枯れ木、墓地の配置。
- 塗り: `python3 ../img.py prompts/paint_cliff.txt paint.png --size 2560x3200 --quality high --image guide_2x.png --image styleref_full.png`
  （`guide_2x.png` は `guide.png` を最近傍で 2 倍、`styleref_full.png` は気に入られている最初のマップ全体）。
- `prep.py paint.png paint_1x.png` → `match.py out/guide.png paint_1x.png pts.npy 128` → `cliff_stage.py out paint_1x.png pts.npy stage`
- 自動チェック: `mask_raised.txt` で作ったマスクを 1/2 にして `match.py st_paint.png m_1x.png pts_mask.npy 128` → `check.py stage paint_1x.png m_1x.png pts_mask.npy report.jpg`

結果（採用した 4 枚目の生成）: 補正後のずれ 平均 1.7〜2.6 px、骨組みの立体物の 97 % が絵にも描かれ、絵の立体物の 99 % が骨組みにある。
ランダム歩行 800 回（32 地点から）で引っかかり 0。

わかったこと:
- 段差があっても前後関係は「どちらが南にあるか」だけで決まるので、絵の 1 ドットごとに「南北の位置」を 1 つ持たせれば足りる（`vox.py` 冒頭）。
- 画家（画像モデル）は細い枝や木の大きさを盛りがち。最初の骨組みでは枯れ木を小さく作ったため、塗りで倍の高さに描かれ、枝の前後関係が合わなかった。
  骨組み側の木を大きく作り直して塗り直すと合った。「絵で目立たせたい物は骨組みでも同じ大きさに作る」。
- 4 枚生成して 1 枚は中段に木を 1 本描き足した。自動チェックの全体図（青＝絵にだけある立体物）で見つけられる。
- 未対応: 橋の上と下を両方歩くような立体交差（同じ画面の位置に歩ける場所が 2 つある場合）。いまは手前を優先して奥を通行不可にしている。

## HD-2D 表示（`site/hd.js`）

骨組み先行で作ったマップは、絵の 1 ドットごとに「3D のどこにあるか」が `height.png` から分かる。そこで塗った絵を
そのまま立体（1 ドット 1 頂点の浮き彫り）に貼り、本物のカメラで映す。絵は描き直さない。

- 遠近感（カメラ距離を 3 段階）、奥行きのぼかし、光のにじみ、立体に沿って当たるランタンの光、雲海に溶ける崖。
- 主人公は立て板で、物陰に入ると本物の奥行き判定で隠れる（2D 版の規則と同じ結果になる）。
- 手前の物の裏に隠れていた地面は絵に無い。奥の面を手前の物の下へ延長し、奥側の色をにじませて補う（`fill`）。
- 骨組みと塗りは数ドットずれる（枝は細く、門の凹凸は数が違う）。`check.py` が書く `raised.png`（絵描き自身の
  「立っている物」の輪郭）で、浮き彫りの縁を塗りに合わせて削る・足す。
- 限界: カメラは回せない（絵が 1 方向からしか無い）。立体感を「強」にすると、補った地面のぼやけが見えてくる。
  頂点が約 400 万あるので、実機での速度は未計測（遅いと自動で解像度を下げる。`?q=low` で半分固定）。
- 確認用: `?hdshow=back`（補った面だけ）、`?hdshow=main`、`?keep=1`（画面の読み出し用）。


## 月光樹の浮き島（`isles_world.py`、`site_isles/`）

崖の修道院より大きい 1920×1790 の 2 枚目。雲海に浮かぶ 7 つの島（船着き、石の環、水鏡、結晶、月光樹、月の門、泉）を
階段と橋でつなぐ。手順は崖と同じで、違う所だけ書く。

1. `isles_world.py out` … 骨組みを焼く（約 2 分）。`under.png` と `behind.png`（下記）も出る。
2. 塗り: 2 倍だと画像モデルの上限を超えるので、全体を 1.5 倍（2880×2752）で 1 回生成した（`prompts/paint_isles.txt`）。
   上下 2 枚に分けて 2 倍で生成する案も試したが、島の裏側の描き方が 2 枚で食い違うので使っていない。1.5 倍でも密度は足りた。
3. この絵は縦に約 3 % 伸びて返ってきた（`match.py` の dy が下端で 52 ドット、探索範囲ぎりぎり）。縮小のときに
   その伸びを一緒に戻し（2880×2752 → 1928×1788 にしてから 1920×1790 に置く）、焼いたデータも下 50 行を切った
   写し（`outc/`）を使う。絵の再標本化は縮小の 1 回だけ。
4. `isles_stage.py outc paint_1x.png pts.npy stage` … 光（ランタン、結晶、月光樹、紋）、会話、蛍、水面、`hd` の設定を書く。
   北側の縁は絵のほうが数ドット小さいので、空に塗られた所は歩けなくする。
5. マスク: `prompts/mask_isles.txt` を 1.5 倍の絵に掛ける → `match.py stage/st_paint.png m_1x.png pts_mask.npy` →
   `check.py stage paint_1x.png m_1x.png pts_mask.npy report.jpg adopt`。

結果: 骨組みの立体物の 98 % が塗られ、塗られた立体物の 85 % が骨組みにある（差は、マスクが地面の光る紋を「立っている」と
見なした分と、木の根）。乱数歩行 800 回で詰まり 0、7 か所の会話地点すべてに歩いて行ける（`/home/user/tw/rw_any.js` 相当）。

わかったこと:
- 絵描きが足した立っている物（月光樹の両脇の石碑 2 本）は `check.py … adopt` が拾う。マスクにだけある塊のうち、
  縦長で歩ける地面の上にある物に、足元の当たり判定と「立て板」の高さを与える（横長の物＝地面の紋は触らない）。
- 手前の物の裏（絵に描かれていない所）は、まわりから推定せず骨組みから焼く。`under.png` = その視線が最初の面のあとで
  最初に入る地面（草、道、岩、水。0 = 裏は空）、`behind.png` = 最初の面のあとで最初に入る別の面（空気を挟むか、
  材質が変わる所。幹から地面、壁から床もこれ）。HD-2D 側は裏を 2 層作る: 地面の層と、物がもう一つ挟まる所の層
  （門の塔の裏の柱、葉の裏の枝）。色は見えている続きから取り、縁で鏡写しにした絵柄を重ねる（石畳は石畳として続く）。
  骨組みに無い物は従来どおりまわりから推定し、空と地面の多いほうを取る。
- 前は推定で縁から 60 ドットしか作らず、門（床を 100 ドット隠す）の裏に穴が残った。また「2 枚目の面が無い = 空」と
  していたので、太い幹のように視線がそのまま地面へ入る物まで「裏は空」になっていた。
- 樹冠は幹の手前に張り出させない。張り出した樹冠は、HD-2D で見る角度が少し変わると幹から上下にちぎれる
  （絵描きは幹、枝、葉をひと続きに描く）。視線に沿って奥へずらし（`isles_world.py` の `CS`）、樹冠の下端を幹と同じ
  奥行きに置く。絵に写る形は変わらないので、塗り直しも位置合わせのやり直しも要らない。
- 絵で空になっている所は、骨組みに面があっても面なしとして扱う（骨組みの縁は絵より数ドット太い）。
- 残る乱れ: 光る物が地面に落とした光（結晶やランタンのまわりの明るい輪）は地面に描かれているので、立体感を強くすると
  物から少しずれて見える。

## 描き込み 2 倍の見本（`isles_hi.py`、`site_isles_hi/`）

月光樹の浮き島のうち、石の環の島と船着き（1x で x 416〜1504、y 990〜1790）を、背景 2 倍の細かさで作り直した見本。

1. 今の絵のその範囲を 3 倍に拡大（最近傍）し、`prompts/paint_isles_hi.txt` で「3 倍の解像度で描き直す、配置は固定」と
   gpt-image-2 に 3264×2400 で描かせる。1.5 分の 1 に縮めて 2176×1600（= 2 倍）。配置のずれは ±4 ドットだけだった。
2. `match.py old2x.png d_near.png pts.npy 200` で位置合わせ、`isles_hi.py ../site_isles d_near.png 出力 pts.npy` が
   データ（高さ、床、裏、歩ける所）を切り出して 2 倍にし、絵に合わせて動かす。map.json も座標を 2 倍にする。
3. `map.json` の `"view": 2` で画面は 1920×1080 マップドットになり、キャラは同じドット数のまま画面の 7 % ほどになる。
   `hd` の `S` を 2 倍、`cutSides`（切り出しの左右の端を雲に溶かす）、`dofScale`、`range`、`band`、`bloom`、`bloomTh`、`bloomWide` で
   ぼかしと光を強めた。`hd.js` のドット単位の決まり（JUMP など）は `view` に合わせて自動で倍になる。
