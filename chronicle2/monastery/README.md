# 鐘のならない修道院（フィールド試作）

続編のフィールドの作り方を確かめるための、1マップだけの試作です。
Blender の中で修道院を立体として組み、斜め上の固定カメラから高精細な一枚の絵（2880×3072）に描き出し、その上をドット絵の主人公が歩きます。

- `site/` ブラウザで動くデモ一式。`index.html` と画像、`map.json`。
- `build/` 絵とデータを作り直すためのスクリプト。

## 作り直し方

```
pip install bpy numpy pillow        # bpy は Blender 本体を Python から使う部品（5.2 系、Python 3.13）
cd build
SAMPLES=96 NOISE=0.03 python3 scene.py   # 立体を組む、描き出す、判定を焼く → work/beauty.png, work/bake.npz, work/meta.json（4コアで約11分）
python3 sky.py                      # 二つの月の空                      → ../site/sky.jpg
python3 post.py                     # 霧、色、筆のタッチ、ゲーム用データ → ../site/map.webp ほか
python3 hero_import.py シート.png シート.json   # 主人公の取り込み      → ../site/hero.png, ../site/hero.json（3つ目に名前を書くとその名前で）
```

### 背景の仕上げは2通り

- **ドット絵**（`site/px/`、ページの初期表示）: 96ドットの主人公と同じ大きさのドット（1 単位 32 ピクセル、絵は 1920×2048、画面は 960×540）で、
  輪郭線を引き、色を 96 色に絞り、霧とにじみを控えめにした版。キャラクターのドット絵と絵柄をそろえるためのものです。
- **絵画調**（`site/` 直下）: 1 単位 48 ピクセルで滑らかに描き、筆のタッチをかけた版。

ドット絵の版は、置き場所を分けて同じスクリプトを `STYLE=pixel` で動かします。

```
cd build
WORK=$PWD/work_px RES=2 DRES=2 SAMPLES=96 NOISE=0.03 python3 scene.py
WORK=$PWD/work_px SITE=$PWD/../site/px STYLE=pixel RES=2 python3 sky.py
WORK=$PWD/work_px SITE=$PWD/../site/px STYLE=pixel python3 post.py
```

いま入っているドット絵の版は、描き出しの時間を省くため、絵画調の描き出し（2880×3072）を 1920×2048 に縮めたものを `work_px/beauty.png` として使い、
判定だけ `NORENDER=1` で焼き直しています。`post.py` は `STYLE=pixel` のとき `COLORS`（色数）、`LINE`（輪郭の濃さ）、`MIST`、`GAMMA`、`RAMP` を受け取ります。

`scene.py` は環境変数で動きを変えられます。`SAMPLES` と `NOISE`（描き出しの丁寧さ）、`RES`（絵の細かさ。既定 3 で 1 単位 48 ピクセル）、
`QUICK=1`（判定の焼き直しを省く）、`NORENDER=1`（描き出しを省く）、`TUNE='{"key":5.6,...}'`（光の強さや色を試す）、
`CROP=x0,y0,x1,y1` と `BEAUTY=名前.png`（一部分だけ素早く描き出して確かめる。座標は 960×1024 の配置図のピクセル）。
`post.py` は `PAINT`（筆のタッチの強さ、0 で無し）と `Q`（画質）を受け取ります。

手元で動かすときは `site/` を静的サーバーで開きます。`index.html` は公開先で外枠が付く前提の書き方（`<html>` などを書かない）なので、
素のまま開くと文字化けすることがあります。その場合は `<meta charset="utf-8">` を先頭に足してください。

## 仕組み

| ファイル | 役割 |
| --- | --- |
| `build/kit.py` | 立体を作る部品。箱、回転体、崩れた壁、尖頭アーチ、木、葉など。面ごとに色を持たせます。 |
| `build/scene.py` | 修道院そのもの。地形、石段と門、墓地、身廊、鐘楼、回廊と泉、崖の見晴らし台、森、光、カメラ。 |
| `build/bake.py` | 同じ立体に光線を当てて、ゲーム用の情報を取り出します。画素ごとの高さ、面の向き、素の色。地面の格子ごとの「歩けるか」と床の高さ。 |
| `build/post.py` | 霧、灯のにじみ、黄昏の色合わせ（コンセプトスケッチの5色に寄せる）、筆のタッチ。ゲームが読む画像と `map.json` を書き出します。 |
| `build/sky.py` | 崖の向こうの空。沈む白い月と昇る黒い月。 |
| `build/hero_import.py` | 主人公のスプライトシートを取り込みます。各コマの灯の位置を測って `site/hero.png` と `site/hero.json` を書き出します。 |
| `site/index.html` | ゲーム本体。素の JavaScript と canvas だけで動きます。 |

### カメラの決まり

立体、判定、ゲームのすべてが同じ式を使います。

- 配置は 1 単位 = 16 ピクセルの方眼（960×1024）で決めてあり、絵はその 3 倍（1 単位 48 ピクセル、2880×3072）、
  画素ごとの判定データは 1.5 倍（1 単位 24 ピクセル、1440×1536）で作ります。ゲーム画面は 1440×810 です。
- カメラは北を向いて見下ろす平行投影。`SIN = 0.75`、`COS = sqrt(1 - SIN^2)`。
- 画面座標: `sx = (x - X0) * S`、`sy = SY0 - (y * SIN + z * COS) * S`（絵では `S = 48`、`X0 = -30`、`SY0 = 2925`）。
- カメラからの奥行き: `d = y * COS - z * SIN`。主人公の各ピクセルより手前にある絵のピクセルが、主人公を隠します。

### 立体に付ける種類

`floor`（歩ける面）、`solid`（壁や柱や墓石。通れない）、`soft`（草や落ち葉。通れる）、`cover`（屋根など。判定には入れない）。
歩ける範囲は、床に頭上の余裕があるか、段差が 0.45 以下か、出発点からたどり着けるかで自動的に決まります。

### 主人公のスプライト

`site/hero.png` は横4コマ（立ち、左足、通過、右足）× 縦4コマ（下、左、右、上）。いまの絵は1コマ 48×64、足元は各コマの (24, 60)、1コマ 160 ミリ秒です。
コマの大きさ、足元の位置、体の高さ、歩く速さ、各コマの灯の位置は `site/hero.json` に入っていて、ゲームはそこから読みます。
縦を8コマにすると斜め移動の絵も使われます。行の順は 下、左、右、上、左下、右下、左上、右上 です（4行のシートなら斜めに歩くときも上下左右の絵で表示します）。
体は何ドットで描かれていても世界の 3 単位（画面で 144 ピクセル）の高さに表示されるので、96 ドットの絵に替えればそのまま細かくなります。
差し替えるときは `python3 build/hero_import.py 新しいシート.png 新しいシート.json` を実行するだけです。

見比べのために、同じ主人公を 96 ドットで描いた版（1コマ 96×128、足元 (48, 120)）も `site/hero_hd.png` と `site/hero_hd.json` として入っています。
画面の下の「主人公のドット絵」のボタンで 48 ドットと 96 ドットを切り替えられます。こちらを作り直すときは最後に名前を付けて
`python3 build/hero_import.py シート.png シート.json hero_hd` とします。
