# サイト運用プレイブック（monometri / sukinobi / mononippon）

目的は2つ。(1) 各サイトの検索表示回数（IMP）の最大化、(2) アフィリエイトのCV（最重要KPI）。
権限: 運営判断は全面委任済み（記事の追加・修正・削除・整理、公開まで）。ただし下記ガードレールを守る。

## 前提（2026-10 時点）
- データ取得: `site-ops/tools/`（環境変数 `GOOGLE_SA_JSON` / `GA4_PROPERTY_IDS`。キーはリポジトリに置かない・チャットに貼らない）。
- mononippon: リポジトリ `YukiIkemori/mononippon`。公開は `ops/firebase-release.json` を main で更新して実行（詳細は同リポジトリの `docs/CONTENT-OPERATIONS.md`）。
- monometri / sukinobi: 旧サーバー上の静的サイト。Firebase + GitHub へ移行中（別担当が作業中）。リポジトリができるまでは「観測のみ」。
- Amazon API は保留。CVは各アフィリエイト管理画面の実績で判断（GA4のアウトバウンドクリックは補助指標）。

## 原則
1. トラフィックが少ない間は、反応しすぎない。同じ期間どうし（28日 vs 前28日）で比べ、1〜2週間で結論を出さない。
2. 変更したページは変更日を記録し、変更前後を比較できる期間が貯まるまで再編集しない（最低14日）。
3. 優先順位: ①表示は多いがCTRが低いページ（タイトル・説明文） ②8〜20位のクエリ（加筆） ③CVに近い購入ガイドの導線（比較表・CTA・商品の適合） ④需要が確認できた周辺トピックの新規記事。
4. 事実を作らない（試用・測定・レビュー・在庫を捏造しない）。商品リンクは型番とマーケットを一致させる。
5. 本数のノルマは置かない。伸びた分野を伸ばす。

## ガードレール
- 削除・URL変更は必ず301リダイレクト付き。サイトマップ・内部リンク・canonicalを整合させる。
- 本番ドメインのDNS変更・メール(MX)に関わる変更は行わない（依頼者に案内する）。
- 公開前にそのサイトのビルド検証を全て通す。失敗したら公開しない。
- 秘密情報（鍵・トークン）をコミットしない。

## 定期実行

| 日次 | 毎日 07:xx | 3サイトの死活（トップ・サイトマップ・主要URLが200か）、GSCのインデックス/クロール異常、IMPの急落（前週同曜日比 -50%以下）。異常時のみ対応、平常なら短い記録のみ。 |
| 週次 | 月曜 09:xx | `tools/weekly_report.py` で分析。優先順位に沿って既存記事の改善→必要なら新規記事→公開。結果を各サイトの `ops/` に記録。 |
| 月次 | 1日 10:xx | 28日/前月比のレビュー、記事の統合・削除候補、内部リンク構造、構造化データ・AIO（要点が引用されやすい構成）の見直し、翌月のテーマ決定。月報を作成。 |

## 記録
各サイトのリポジトリ `ops/` に日付付きJSON/MDで、何を見て・何を変えて・何を次に比較するかを残す。
