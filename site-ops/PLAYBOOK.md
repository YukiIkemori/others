# サイト運用プレイブック（monometri / sukinobi / mononippon / asiavela）

目的は2つ。(1) 各サイトの検索表示回数（IMP）の最大化、(2) アフィリエイトのCV（最重要KPI）。
権限: 運営判断は全面委任済み（記事の追加・修正・削除・整理、公開まで）。ただし下記ガードレールを守る。

## 原則
1. トラフィックが少ない間は、反応しすぎない。同じ期間どうし（28日 vs 前28日）で比べ、1〜2週間で結論を出さない。
2. 変更したページは変更日を記録し、変更前後を比較できる期間が貯まるまで再編集しない（最低14日）。
3. 優先順位: ①表示は多いがCTRが低いページ（タイトル・説明文） ②8〜20位のクエリ（加筆） ③CVに近い購入ガイドの導線（比較表・CTA・商品の適合） ④需要が確認できた周辺トピックの新規記事。
4. 事実を作らない（試用・測定・レビュー・在庫を捏造しない）。商品リンクは型番とマーケットを一致させる。
5. 本数のノルマは置かない。伸びた分野を伸ばす。

## ガードレール
- 削除・URL変更は必ず301リダイレクト付き。サイトマップ・内部リンク・canonicalを整合させる。
- 本番ドメインのDNS変更・メール(MX)に関わる変更は行わない（依頼者に案内する）。
- 公開前にそのサイトのビルド検証を全て通す。失敗したら公開しない。
- 秘密情報（鍵・トークン）をコミットしない。

## 記録
mononippon は同リポジトリの `ops/mononippon-growth/` に、日付付きで残す。monometri / sukinobi は main への push が本番を更新するため、記録だけのコミットを避け、`site-ops/records/` に日付付きMDで、何を見て・何を変えて・何を次に比較するかを残す。

## 実行環境の注意
定期実行は『毎回新規セッション』ではリポジトリにアクセスできないため、運用セッション（persistent）に宛てている。クローンが消えていたら add_repo で再取得し、1つずつクローンする。
