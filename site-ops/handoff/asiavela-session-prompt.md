- 運用ツールと記録は `asiavela/ops/`（tools/ と records/）に置く。このパスはデプロイを起動しない。リポジトリの既存の進め方（ブランチ→PR→マージ）に合わせる。

## 2. 定期実行（このセッション自身に届くように作る）
- create_trigger を「このセッションに戻す」既定モードで作る（毎回新規セッション型は不可。リポジトリに触れないため）。
- 日次 毎日 07:18 JST、週次 月曜 09:22 JST、月次 1日 10:17 JST（CRON_TZ=Asia/Tokyo）。
- 作成後、最初の発火がこのセッションに届いたかを必ず確認する。届かなかった場合（別の空セッションに届く事例が過去に2回あった）は作り直して報告する。

### 日次（短く）
トップ・sitemap.xml・robots.txt と sitemap から間引いた数件が200か。Search Console の日次IMP/クリックで前週同曜日比 -50% 以下の急落がないか。表示のあった上位ページに新しい404・多段リダイレクトがないか。asiavela ワークフローの直近の失敗。平常時は「異常なし」と1〜2行。大きな変更・新記事は日次ではしない。

### 週次
直近7日と前7日・28日の比較（国別・言語別・ページ別・クエリ別）、CTRの低い上位ページ、8〜20位のクエリ、表示のあった全URLの状態（200 / 301→着地先 / 404）、サイトマップ件数とGoogleの読込日、新しい国のURL検査（抜き取り）、GA4。改善は優先順位どおり ①表示が多くCTRが低いページのタイトル・説明文 ②8〜20位のクエリの加筆 ③送客導線 ④需要の確認できた新規記事。

### 月次
国・言語ごとの伸び、統合・削除候補（301必須）、内部リンク、構造化データ、AIO、表示速度、サイトマップの分割要否。翌月のテーマと判断基準を決める。深掘りが重い場合はサブエージェントに国ごとに分けてよい。

## 3. 運用ルール
- 変更したページは最低14日は再編集しない（変更日を記録）。他者（別AI・私）の直近コミットを必ず確認してから触る。同じ記事を他のセッションが編集中なら触らない。
- 削除・URL変更は必ず301。転送は1回で最終URLへ（多段にしない）。代わりの記事が無いものは404のままでよい（国トップへの転送はソフト404扱いになり得る）。
- 事実を作らない（体験談・価格・在庫・営業時間の捏造をしない）。出典で確かめられないことは書かない。
- アフィリエイトの実績は私が「売上が出たら伝える」ので、それまで依頼しない。判断は Search Console のクリックと GA4 の外部クリックで。
- DNS・メール(MX)に関わる変更はしない。ビルド検証（validate.py ほか）を通らないものは公開しない。
- 編集・公開の判断の前と、完了を宣言する前に advisor を呼ぶ。
- mononippon 本体（`asiavela/` 以外）には触らない。mononippon の旧旅行URL→asiavela の転送表 `content/asiavela-redirects.json` を変える必要が出たら、私に提案する（mononippon 側の公開が要るため）。
